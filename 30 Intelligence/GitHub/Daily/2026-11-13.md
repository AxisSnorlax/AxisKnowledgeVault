### P1 — WinUI：发布通道与合成模式一起记录

[WinAppSDK 2.6.5 对应的 WinUI 发布页](https://github.com/microsoft/microsoft-ui-xaml/releases/tag/winui3%2Frelease%2F2.6.5) 显示 11 月 11 日。它修复多显卡／多显示器渲染、Windows 10 背景透明异常及打包安装问题；缺少所需系统接口时改用 lifted compositor。为处理线程异常，该版回退部分背景变更，使用 System Composition Engine 时不支持 content islands 与 XAML windows 的系统背景。

[官方发行列表中的 2.6.6-experimental](https://github.com/microsoft/microsoft-ui-xaml/releases) 同样显示 11 月 11 日，并明确标为 Pre-release。它扩展 TableView 层级与 `IsLiveShaping`、Chart UI Automation，以及可关闭视口裁剪的滚动属性，后者默认仍为 false。实验功能不并入稳定版可用清单。

对 [[AxisAgent]] 的推论：UI 资格记录除包版本外，还需区分发布通道、系统版本和合成模式；渲染可见、对象身份、实时数据变动及自动化树一致性分别验证。本轮已补入 [[WinUI]]，没有修改项目包或系统设置。

### P2 — OpenBot：应用更新与数据迁移不是同一件事

[OpenBot README](https://github.com/CopilotKit/OpenBot) 将前端、工作台后端和 Agent 执行平台分开，AG-UI 连接 Agent，MCP 连接工具。桌面入口背后仍包含容器服务与相应依赖，不能仅从安装器形式推导执行环境。

[v1.0.2](https://github.com/CopilotKit/OpenBot/releases/tag/v1.0.2) 发布页显示 11 月 11 日：Windows 改用应用自有的 `openbot` Podman machine；此前运行在用户其他机器中的数据仍留在原位置，新机器从空状态开始。更新与卸载也分别处理进程停止和数据保留，较早数据库迁移的回退依赖升级前备份。

工程推论：升级回执需标明旧数据位置、新环境身份及是否迁移；新后端启动成功不证明旧会话已恢复。沿用 [[Durable Agent Runtime Identity]] 的执行环境绑定，本轮未安装、升级容器工具或接入外部服务。

### P3 — Qwen Code：CLI 预览与 SDK 版本分别看

[1.0 Preview 发布记录](https://github.com/QwenLM/qwen-code/releases) 描述不另装 Node.js 的 Windows／macOS／Linux 原生包，并支持会话恢复和非交互执行；[v1.0.0-preview.1](https://github.com/QwenLM/qwen-code/releases/tag/v1.0.0-preview.1) 显示 11 月 12 日，调整登录后的订阅模型目录、thinking budget 映射及 Qoder 并行工具调用。

它仍是预发布。`latest` 入口本轮返回的 TypeScript SDK 版本属于另一条发行线，不能拿它当作 CLI 版本。对 Windows 自动任务，应分别记录实际执行文件版本、账户可用模型和并发策略；模型支持并行调用不证明所有有副作用的工具可并行执行。本轮没有改变此聊天的模型或任务执行方式。

## 本地 AI — TensorFold 的验证粒度

[TensorFold README](https://github.com/ashhart/TensorFold) 将原生引擎、模型格式、后端和具体设备的资格分开；例如它明确某些 GPU 只有 kernel-check 证据，没有完整 checkpoint 服务记录，不能据此认定模型可用。

[v1.2.7](https://github.com/ashhart/TensorFold/releases/tag/v1.2.7) 发布页显示 11 月 11 日，包含长会话缓存恢复、磁盘恢复失败后保留内存状态、损坏 JPEG 拒绝处理及畸形工具调用保留为文本等变化。性能数据限定了机器与场景，属于维护者自报，本轮不引用为本机收益。

[Windows 文档](https://github.com/ashhart/TensorFold/blob/main/docs/WINDOWS.md) 明确当前 Windows 路径为源码构建，部分设备运行记录尚未在维护树复现；结构化输出及 required／named tool choice 还依赖 `tfgrammar.dll`，缺失时对应请求返回错误，普通服务仍可运行。

对 [[AxisAIManager]] 的推论：引擎启动、算子检查、模型服务、结构化输出及质量验收分别记录。接口可访问不能替代特定请求能力就绪；这些原则已在 [[Local-AI]] 中分层，本轮不重复追加，也未构建引擎或下载权重。

[v1.7.1300.1822](https://github.com/SakiRinn/LiveCaptions-Translator/releases/tag/v1.7.1300.1822) 是本轮入口返回的已有版本，页面显示 1 月 18 日，记录减少重复句子翻译、字幕布局及配置变化。Windows 工程借鉴是将识别语言、句段状态、翻译 Provider 和显示历史分开；本地识别不代表后续翻译天然离线。本轮未录音或调用翻译服务。

1. **可用性需要具体条件。** 发布通道、合成模式、设备、模型及请求能力不能由单一版本号概括。
