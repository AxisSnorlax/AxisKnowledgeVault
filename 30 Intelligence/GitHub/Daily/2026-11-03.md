### P1 — FreeToken：支持图片需要核对完整加载合同

[v0.2.1](https://github.com/FlashML-org/FreeToken/releases/tag/v0.2.1) 页面显示 10 月 26 日。其 GGUF 图像输入依赖匹配的 mmproj，匹配条件包括输出宽度、视觉塔和图像 token；加载日志记录实际文件。找不到合适文件或有无法消除的歧义时，模型按纯文本服务。部分架构、模板和 GGUF 转 FTW 路径仍有文本限定，不能仅凭模型家族名称宣称视觉能力可用。

对 [[AxisAIManager]] 的设计推论：将主模型、投影文件、模板、Runtime 版本与实际启用模态共同记录；请求要求图片能力时，应确认该路径确实被接受并验证结果。增量加入 [[30 Intelligence/GitHub/Local-AI|Local-AI 趋势索引]]。

[README](https://github.com/FlashML-org/FreeToken) 提供 Windows/Linux 桌面下载入口，但 [CLI 安装文档](https://github.com/FlashML-org/FreeToken/blob/main/docs/install.md) 当前列出 Linux x86_64、NVIDIA 与 CUDA 13 要求。两条交付路径不能混用为用户 Windows 本机资格证明。大模型速度、显存收益和硬件范围均为项目方声明，本轮未复测，也不替换既有推理主路径。

### P2 — Worktrunk：Hook 的执行方式会改变输入合同

[README](https://github.com/max-sixty/worktrunk) 将分支、工作树与 Hook 工作流组合；在 Windows 上还说明 `wt` 与 Windows Terminal 命令重名，提供 `git-wt` 入口。这里是工具观察，本轮未安装或创建工作树。

[v0.81.0](https://github.com/max-sixty/worktrunk/releases/tag/v0.81.0) 页面显示 10 月 20 日：前台串行 Hook 可继承标准输入进行交互，并发/后台 Hook 读取 EOF；原先从 stdin 获取上下文 JSON 的方式改变，模板对象也需明确序列化。该版本还指出，并发执行的清理 Hook 若写共享状态需自行协调。

对 Windows/.NET Agent 宿主的推论：配置的来源、执行模式、输入格式与目标工作树应进入诊断；不能把“同名 Hook 仍存在”视为旧脚本行为不变。工作树隔离也不能自动解决共享缓存、端口或外部资源的竞争。已有运行时并发原则继续保留，不重复追加长期页。

### P2 — LibreHardwareMonitor：缺失读数不能伪装成零

[官方 README](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor) 将 .NET 应用与可复用库分开，并说明部分传感器需要额外权限，不同硬件的读取方式存在差异。[v0.9.6](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/releases/tag/v0.9.6) 页面显示 2 月 14 日，列出错误零温度读数、重复硬件条目及新增 GPU 遥测等维护记录，是既有版本复核。

对 [[AxisAIManager]] 和 Windows 工具的推论：观测记录区分有效数值、未提供、读取失败与过期；硬件身份、观测来源和采样时刻与数值一起保存。未读到温度或占用不能直接记成 0。本轮没有安装驱动、提升权限或测量用户硬件。

## WinUI 3、WPF、Avalonia 与 .NET 工程借鉴

[Avalonia 12.1.5](https://github.com/AvaloniaUI/Avalonia/releases/tag/12.1.5) 发布页显示 **11 月 2 日**，本轮已核对维护内容：Windows 的移动/缩放拖动支持触控、Alt+Space 系统菜单、索引器绑定通知、树节点自动化展开折叠，以及移动目标上的点击、双击按键一致性和文本命中测试修复。

对工程工作台，这些提供了具体的回归场景：触控与鼠标走不同输入路径时，窗口操作、点击目标、文本选择和 UI 自动化都应有独立验证。发布说明不是用户项目兼容性通过，也不构成立即升级要求。

[WinUI latest 入口](https://github.com/microsoft/microsoft-ui-xaml/releases/latest) 返回 2.5.1 且带四日前缓存；[WPF latest 入口](https://github.com/dotnet/wpf/releases/latest) 返回 v10.0.13 且带三日前缓存。因此这两项仅作为已返回的历史版本信息，不保证当天没有其他新发布，不据此改变框架选型。

本轮仅研究文档与发行记录，未修改、构建或测试 .NET 项目。实际开发仍按用户要求应用相关已安装 dotnet/skills。

## 长期判断

对 Agent 调用模型或 MCP 工具的共同启示是，实际能力由当前加载状态和版本决定；不能让静态目录条目代替调用前检查。本轮没有获得需要改动 MCP 权限模型的新证据，保留既有边界。

1. **能力属于实际制品组合。** 主模型、配套文件、模板和 Runtime 共同决定可接受的输入模态。
2. **工作流配置也有协议版本。** 串行/并发、stdin、序列化和共享资源约定需要一起核对。
3. **缺失观测保留缺失状态。** 数值、来源、时间与有效性共同构成证据，不能通过默认零值制造确定性。

本轮只向 Local-AI 索引追加多模态能力确认的增量，其他长期页不机械更新。
