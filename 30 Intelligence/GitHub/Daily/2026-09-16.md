# GitHub Trending — 2026-09-16

## 今日结论

今天真正值得长期沉淀的不是新的“万能 Agent 框架”，而是四个更具体的工程信号：

1. **Harness 开始具备受控自我改进能力**：可信 Base Contract 保持不可变，Prompt Note / Memory / Skill / Subagent Spec 等补充状态允许通过小型、证据驱动的 Delta 更新，并且必须可 Snapshot / Rollback。
2. **Context / Knowledge 从平面 RAG 向可追溯 Context Graph 演化**：Fact、Decision、Source、Conflict、Temporal Snapshot 与 Provenance 开始成为一级对象。
3. **专业软件的 Agent Surface 继续收敛到确定性合同**：稳定对象地址、结构化 JSON、原子事务、验证与可视化闭环比“给 UI 加一个聊天入口”重要得多。
4. **Coding Agent 的代码上下文开始从 Embedding-only 向 Structural Intelligence 演化**：AST / Symbol / Call Graph / Dataflow / Structural Patch 与 MCP 正在组成新的代码理解层。

## 值得关注

### PrimeIntellect-ai/prime-agent

- 方向：AI Coding / Long-running Agent / Continual Harness
- 今日增长：GitHub Trending 约 **+2,655 stars/day**。
- 项目：https://github.com/PrimeIntellect-ai/prime-agent
- 为什么值得看：其核心不是普通 Memory，而是 `Continual Harness`：补充 Prompt、Memory、Skill Description 与 Subagent Spec 可作为 Durable State 保存，并通过 `/refine` 做小型、证据驱动的更新；Base System Prompt 明确保持 immutable，更新前后可保留 snapshot 并 rollback。
- 另外值得注意：后台 Agent、Persistent REPL、Compaction、Goal、Heartbeat 与 Retained Subagent 共同服务长任务连续性。
- 安全边界：项目明确提醒 Worker/Kernel 隔离主要服务生命周期与恢复，并不等价于 Security Sandbox；生成代码仍可能拥有用户权限。
- 对 [[AxisAgent]] 的借鉴：把长期自适应设计成 `Immutable Base Contract + Mutable Supplemental Harness State + Evidence-backed Delta + Verification + Snapshot/Rollback`，而不是允许 Agent 自行重写系统规则。Permission / Approval / Security Policy 必须留在不可变 Runtime 边界。
- 长期沉淀：[[Agent Capability Packaging]] · [[Agent Memory and Knowledge Lifecycle]] · [[Deterministic Agent Runtime]]。

### semantica-agi/semantica

- 方向：Context Graph / Provenance / Decision Intelligence / Accountable AI
- 今日增长：GitHub Trending 约 **+967 stars/day**。
- 项目：https://github.com/semantica-agi/semantica
- 为什么值得看：它把 Context Graph、Decision、Provenance、Conflict Detection、Deterministic Reasoning 与 Point-in-time Snapshot 作为同一知识基础设施，而不是只把文本切块后放进向量库。
- 关键工程信号：Fact 有 Source Provenance；Decision 是可查询一级对象；Knowledge 可以检测冲突和语义重复；时间点 Snapshot 可用于追溯“当时 Agent 知道什么”。
- 对 [[Axis Knowledge Vault]] / [[AxisAgent]] 的借鉴：长期知识应逐步增加 `source / revision / provenance / conflict / supersedes / valid-time / decision-link` 等元数据；Decision Record 与 Fact Knowledge 应分开建模。
- 边界：这不意味着当前 Git + Markdown + Obsidian 应被替换。更合理的是保持人类可读 Markdown 为长期载体，并让 Graph / FTS / Vector 成为可重建派生层。
- 长期沉淀：[[Agent Memory and Knowledge Lifecycle]]。

## 今日长期判断

### 1. Immutable Base Contract + Mutable Harness Delta

```text
Immutable Base Contract
  ├── Security Boundary
  ├── Permission Rules
  ├── Core Runtime Policy
  └── Verification Invariants
        ↓
Mutable Supplemental Harness State
  ├── Prompt Notes
  ├── Memories
  ├── Skills
  └── Subagent Specs
        ↓
Evidence-backed Delta
  ↓
Validate
  ↓
Snapshot / Apply / Rollback
```

Agent 可以学习，但不能通过“自我改进”改掉不可越过的安全与正确性合同。

### 2. Accountable Knowledge

长期知识不应只有 `text + embedding`。对高价值长期结论，至少应能够回答：

- 来源是什么？
- 来源的 commit / revision / hash 是什么？
- 这是一条 Fact、Decision、Working Thesis 还是 Derived Explanation？
- 是否与既有知识冲突？
- 是否已被 supersede？
- 在某个时间点，当时有效版本是什么？
- 哪个 Run / Research / Review 将它 Promote 为长期知识？

### 3. Structural Code Intelligence

Coding Agent 的代码检索建议逐渐分层：

```text
Exact / FTS
  ↓
Symbol / AST
  ↓
Reference / Call Graph
  ↓
Dataflow / Dependency
  ↓
Semantic Retrieval
  ↓
Structural Patch + Diff + Verification
```

Embedding 仍有价值，但不应承担结构关系和精确修改的全部职责。

### 4. Professional Surface = Deterministic Contract

专业软件给 Agent 的正式 Surface 应优先拥有：

- stable object identity / path；
- typed / structured schema；
- structured errors；
- atomic mutation / rollback；
- read / safe-write / high-risk-write permission；
- validation；
- render / observe / verify；
- CLI / RPC / MCP 等多个 adapter 共享同一 Domain Contract。
