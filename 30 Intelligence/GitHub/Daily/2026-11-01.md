## 今日结论

### P1 — Unity 官方插件：领域技能不等于完整撤销合同

[当前 README](https://github.com/Unity-Technologies/unity-agent-plugin) 将插件定位为 Unity 6+ 的官方游戏开发工作流，并说明可通过 Unity CLI 操作已打开的 Editor，创建对象、修改导入设置或执行 C#。这属于领域工作流与真实编辑器能力的组合，不能与社区 `CoplayDev/unity-mcp` 混为一个项目。

README 同时明确：插件可能直接修改脚本、场景与资产，并非所有修改都会被记录或能在 Editor 中撤销。[Releases 页面](https://github.com/Unity-Technologies/unity-agent-plugin/releases) 本轮没有发行条目，因此不把 README 中的示例版本当作已核对的最新 GitHub Release。

对 [[AxisAgent]] 和专业桌面软件的设计推论：工具应声明具体的撤销覆盖范围、保存位置与恢复路径；调用前保存适用基线，执行后验证实际结果。编辑器 Undo、Git 文件恢复与外部副作用补偿是不同能力。增量加入 [[Professional Software Agent Surface]]；本轮未安装插件或执行 Unity 代码。

### P1 — Handy：转录、复制与粘贴分开确认

[官方 README](https://github.com/cjpais/Handy) 描述本地 VAD、语音模型与快捷键听写流程，支持 Windows/macOS/Linux。它是本地语音应用样本，不是 WinUI 或 .NET SDK。

[v0.9.8](https://github.com/cjpais/Handy/releases/tag/v0.9.8) 页面显示 10 月 3 日，记录无可用转录模型时不开始录音、仅在剪贴板写入后显示复制成功，以及短录音后释放取消快捷键等修复。这些是既有版本的本轮复核，不是今天新增功能。

对 [[AxisAIManager]] 的推论：录音许可、模型就绪、转录完成、剪贴板写入和目标应用接收不能合并成一个成功状态。应用提供离线转录声明不代表本轮已经验证隐私或准确率；已有音频合同可以容纳这些检查点，不重复追加长期索引。

### P2 — FlyPhotos：输入命中与窗口几何是可验证行为

[README](https://github.com/riyasy/FlyPhotos) 说明应用基于 WinUI 3、WinRT、Win2D，并采用 Native AOT。其快速启动和流畅浏览属于项目自述，本轮没有独立 Benchmark。

[v2.7.4](https://github.com/riyasy/FlyPhotos/releases/tag/v2.7.4) 显示 10 月 13 日，包含以触点为中心的缩放、图片外手势移动窗口、窗口适配图片并限制在工作区内等交互；其中窗口恢复的适配行为标为实验性。对 Windows/.NET 图片或工程视图，应分别核对输入起点、缩放锚点、最小尺寸、工作区边界及多显示器行为，而不是仅凭动画观感比较框架。

## 长期判断

1. **撤销与恢复按操作声明。** 能在编辑器执行，不代表自动记录 Undo；文件基线也不能覆盖所有外部副作用。
2. **完成状态绑定真实落点。** 识别出文字、写入剪贴板和送达目标应用分别验证，界面提示不能提前代替证据。
3. **交互资格和性能宣传分开。** 手势锚点、窗口边界与保存恢复可具体检查，热度和演示不构成框架排名。
