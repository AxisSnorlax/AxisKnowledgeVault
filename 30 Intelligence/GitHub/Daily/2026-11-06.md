### P1 — Auto Ontology：先检查语义与连接，再回答问题

[官方 README](https://github.com/NVIDIA/auto-ontology) 描述从企业元数据构建语义目录，经 MCP／CLI／API 服务 Agent，并在回答中提供 SQL 与结果。它采用 PostgreSQL／pgvector、Python 后端及模型服务；可本地部署应用不等于推理天然离线。仓库宣传的确定性与可靠性是设计目标，本轮未复现评测。[GitHub Releases](https://github.com/NVIDIA/auto-ontology/releases) 当前没有发行条目，因此这是主分支资料观察，不虚构发布版本。

[MCP 文档](https://github.com/NVIDIA/auto-ontology/blob/main/docs/mcp.md) 分开提供 `check_readiness`、`check_answerable` 与 `ask_question`。目录存在不保证数据库连接仍可用；结果最多返回 100 行，并提供数量与截断信息。

对 [[AxisAgent]] 的推论：可回答性预检不是答案正确性的证明；无结果、结果截断、来源不可达和权限不足应保留各自状态。本轮把这一合同补充到 [[Agent Memory and Knowledge Lifecycle]]，继续以 Git／Markdown 和权威项目材料为事实载体，不因出现图谱项目而迁移存储。

## 本地 AI — VibeVoice 流式 ASR 的模型配置边界

[VibeVoice 主仓库](https://github.com/microsoft/VibeVoice) 同时列有长音频 ASR、流式 ASR、CPU 推理与实时 TTS 等路线；不能把一个路线的指标移用给另一个路线。[流式 ASR 文档](https://github.com/microsoft/VibeVoice/blob/main/docs/vibevoice-asr-streaming.md) 描述按音频块输出文字，并从 checkpoint 的 `preprocessor_config.json` 读取 chunk 与 lookahead 参数；示例包含 CUDA 容器、ffmpeg 和持续 WebSocket 会话。

对 [[AxisAIManager]] 的推论：记录模型及预处理配置版本，把训练匹配的分块参数和客户端传输切片分开；断连、取消、末块刷新、时间戳连续性及延迟分布需要在目标运行环境单独验证。这些是候选验收项，不声称上游已全部覆盖。

[发行列表](https://github.com/microsoft/VibeVoice/releases) 当前没有 GitHub Release。文档可用不证明存在已验证的 Windows 原生包；本轮未下载权重、启动容器或测试语音质量。

## 长期判断

1. **语义目录的生命周期与执行连接分开。** 索引仍可查询时，底层数据源可能已经失效。
2. **预检与答案验证分开。** 可回答性、结果完整性、权限可见范围和事实核验共同决定一个结论能否进入长期知识。

本轮仅更新日报与知识生命周期研究页的新段落；已有 Skill、Local-AI、框架长期页保留原有判断。
