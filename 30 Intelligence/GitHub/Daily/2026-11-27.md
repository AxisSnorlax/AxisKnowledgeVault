## P1 — last30days MCP：退出、清理和身份释放

[已合并 PR #1574](https://github.com/mvanhorn/last30days-skill/pull/1574) 描述 Unix 路径中的修复：观察子进程退出后，先保留尚未回收的进程组 leader，完成相关信号清理后再回收，避免旧 PID／PGID 被复用后误作用于其他进程。不支持相应机制的平台走不进行回收后组终止的回退路径。

同一 PR 为 stdout／stderr 捕获设置边界，并将 stdout 超限作为显式错误，避免截断报告被当作完整结果。作者列出测试与跨目标编译检查，本轮未复跑；Unix 的身份保持机制不能直接当作 Windows 行为已通过验证。

Windows/.NET 借鉴：持久 Run ID、进程代次、系统进程号与清理权限分别记录；迟到清理动作需确认目标仍属于本次子进程。输出截断、退出状态及清理结果也应分开。新增内容写入 [[Durable Agent Runtime Identity]]。

## P2 — DBX 0.6.75：停止等待与取消服务端执行

[v0.6.75](https://github.com/t8y2/dbx/releases/tag/v0.6.75) 页面显示 11 月 26 日，收录 [#15362](https://github.com/t8y2/dbx/pull/15362)。该项目将语句预算按操作分类：读取可到时取消；写入默认不限，若配置写入等待上限则停止客户端等待、保留服务端执行；DDL 不受该语句超时限制。

这是 DBX 的具体策略，不推广成所有数据库或所有语句的通用最优设置。PR 也注明方言解析失败不能悄悄套用读取预算，并披露真实数据库验证与未完成的 CLI／界面验证范围；本轮未独立复现。

对 [[AxisAgent]] 的推论：超时回执注明是否发起了取消、服务端是否仍运行，以及如何继续跟踪结果。对可能已经产生副作用的操作，不能仅因等待结束就自动重复发送。沿用 [[Professional Software Agent Surface]] 的不确定写入与读回原则，不重复追加。
