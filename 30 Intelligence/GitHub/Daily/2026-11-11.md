### P1 — ExcelMcp：数据刷新与报表刷新分别核验

[README](https://github.com/sbroenne/mcp-server-excel) 描述通过 Excel COM 操作真实应用，CLI 与 MCP 共用能力；依赖 Windows、桌面 Excel 和交互式用户会话。它与单纯修改文件结构的工具有不同运行条件，本轮没有打开用户工作簿。

[2.6.12](https://github.com/sbroenne/mcp-server-excel/releases/tag/v2.6.12) 发布页显示 11 月 10 日。关键修复是逐个刷新透视表，包括同源但缓存不同的报表，避免汇总仍旧却声称完成。该版还在忙碌错误中附带已确认的阻塞对话框信息；CLI 插件新增快速入门 Skill，不能据此认为 MCP 插件和 VS Code 扩展也内置了同一 Skill。

对 [[AxisAgent]] 与专业工程软件的推论：完成回执应枚举受影响的派生对象，记录刷新／计算／读回结果及未验证项。仅刷新源数据不足以证明图表、缓存或报表已经更新。这项增量已写入 [[Professional Software Agent Surface]]，未将上游修复描述当作本机验收。

### P2 — Microsoft.UI.Reactor：成熟度按功能区分

[Microsoft 官方仓库](https://github.com/microsoft/microsoft-ui-reactor) 将 Reactor 定位为真实 WinUI 3 控件之上的声明式 C# 编写层，可与既有 XAML／MVVM 共存。当前文档分别标记核心 reconciler 为 Preview、DevTools 为 Draft、部分数据／异步能力为 Early；这些标签描述项目自身的验证广度与变动风险，不是稳定性认证。

[0.1.0-preview.17](https://github.com/microsoft/microsoft-ui-reactor/releases/tag/v0.1.0-preview.17) 发布页显示 11 月 5 日，是预发布。它将框架、可选 Advanced／Devtools 包、Skill Kit／CLI 和实验性 Visual Studio 内嵌预览分开；预览工具明确仍有安装、窗口句柄与 DPI 等边界。

对 Windows/.NET 的借鉴：UI 编写方式、底层平台与开发工具资格分开评估；同一版本号不使所有功能达到相同成熟度。可关注增量协调、控件复用和诊断入口，但不据此迁移现有 UI 或默认启用调试服务。本轮向 [[WinUI]] 索引补充这一候选路线。

## 本地 AI — llmfit：能装入不代表后端能执行

[llmfit README](https://github.com/AlexsJones/llmfit) 描述硬件探测、模型容量／速度估计，以及本机测量反馈。[v1.1.20](https://github.com/AlexsJones/llmfit/releases/tag/v1.1.20) 发布页显示 11 月 3 日，修复将 NVFP4／MXFP4 safetensors 仓库错误列为 llama.cpp 可用候选、集群注意力头分割检查和未知 GPU 后端不再默认推断为 CUDA 等问题。

[测量文档](https://github.com/AlexsJones/llmfit/blob/main/docs/benchmarking.md) 要求模型由实际 Provider 服务，再测 tok/s 与首 token 时间；结果先保存本地，分享是另一个动作。本轮未下载模型、运行推理或上传测量数据。

对 [[AxisAIManager]] 的推论：候选记录至少区分模型格式、量化方式、后端、设备和测量来源。容量估计、文件可加载、实际速度和任务质量不能相互替代；社区同型号硬件结果仍不是本机验收。既有 [[Local-AI]] 的容量规划与测量反馈方向保持不变。
