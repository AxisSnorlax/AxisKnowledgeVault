### P1 — VoiceStudio：可描述的能力未必已交付

[当前 README](https://github.com/debpalash/VoiceStudio) 说明本地工作流在用户硬件上运行，远程服务是可选项。[OmniVoice GGUF 文档](https://github.com/debpalash/VoiceStudio/blob/main/docs/engines/omnivoice-gguf.md) 描述独立原生进程与量化权重，同时明确桌面安装包尚未提供该二进制，安装版会显示不可用。不能把源代码路径的能力当作安装包开箱即用能力。

同一文档指出首次生成可能在下载权重，子进程的 GPU 分配不进入应用自身计数。对 [[AxisAIManager]] 的推论：就绪状态应附具体缺失项，冷启动要拆分下载、加载和生成；测量应标明覆盖的进程与设备。将这个增量补入 [[30 Intelligence/GitHub/Local-AI|Local-AI 趋势索引]]，不重复记录泛化的 Engine Registry 模型。

[v0.5.6](https://github.com/debpalash/VoiceStudio/releases/tag/v0.5.6) 发布页显示 9 月 23 日，记录 MCP 在 Docker 下的 HTTP 405 修复，以及兼容 API 的错误状态与真实 MP3 输出调整。这是既有发布复核；当前 main 文档与发行物分开看，不能从 API 名称推导行为已验收。

### P2 — ThinkRail：Agent 工作台也需要可归属的状态和渲染成本

[官方仓库](https://github.com/JetBrains/thinkrail) 以 pi Agent、Git worktree、SPEC.md 图谱和审查界面组成 IDE。当前文档将编辑器、终端、聊天与变更关联到活动工作区，也介绍 MCP 配置与审批行为。工作区分离是代码状态组织方式，本轮没有据此认定它提供 OS 安全沙箱。

[v0.2.0](https://github.com/JetBrains/thinkrail/releases/tag/v0.2.0) 显示 10 月 18 日，列出减少流事件引起的输入区/聊天头部重绘、后台代码高亮和布局重绘隔离。对 WinUI 3/WPF/Avalonia 的借鉴是将高频流内容与稳定输入、导航和布局状态分开观察；这属于跨框架设计推论，不代表上游网页实现可直接套用，也没有实测性能收益。

SPEC.md 可保存项目意图，但实际代码、构建与验证结果仍需单独确认。此样本先保留在日报，不把它等同于已有专业软件 Domain Core 模型。

### P2 — Cindy：共享任务上下文不等于共享全部授权

[README](https://github.com/makecindy/cindy) 将项目界定为桌面、移动端及共享包组成的开源客户端，描述跨 Harness 使用工作区、记忆和工具的连续体验；[安全说明](https://github.com/makecindy/cindy/blob/main/SECURITY.en.md) 另行说明服务端不在该仓库范围内。因此不能将客户端开源直接表述为整个服务端栈均开源。

[v0.1.115](https://github.com/makecindy/cindy/releases/tag/v0.1.115) 显示 10 月 23 日，记录了归档任务前提示关联自动化暂停、账号隔离的未发送草稿，以及路径解析后按实际目标审核等变化。对 [[AxisAgent]] 的推论：任务归档、设备切换和账号切换应明确影响哪些运行状态与授权，而不能仅更新 UI 标签。

上述功能为项目自述与发行说明，本轮没有连接账户、运行远程服务或验证跨设备行为；既有 [[Agent Capability Policy Enforcement]] 与 [[Durable Agent Runtime Identity]] 已覆盖总体方向，不重复追加。

## C#/.NET、WinUI 3、WPF 与 Avalonia

[OpenUtau README](https://github.com/openutau/OpenUtau) 展示编辑器、音素处理和重采样引擎扩展的分离；[0.1.576](https://github.com/openutau/OpenUtau/releases/tag/0.1.576) 页面显示 10 月 20 日，记录 Vogen 渲染固定使用 CPU、渲染器与内存问题的修复。对 .NET 桌面宿主，设备选择应按具体引擎表达，不能用一个全局“支持 GPU”覆盖所有任务。本轮只是发布说明研究，未修改或构建 .NET 项目。

框架 latest 入口本轮仍返回 [WinUI / WinAppSDK 2.5.1](https://github.com/microsoft/microsoft-ui-xaml/releases/tag/winui3/release/2.5.1)、[WPF v10.0.13](https://github.com/dotnet/wpf/releases/tag/v10.0.13)、[Avalonia 12.1.4](https://github.com/AvaloniaUI/Avalonia/releases/tag/12.1.4)。WinUI、WPF 返回带昨日缓存时间，本轮不据此保证没有其他新发布；没有足以改变选型的新增证据，不机械更新三个框架索引。

今天的 Windows 工程关注点是工作区归属、流式界面的更新范围和引擎可用性，而非框架迁移。实际 .NET 代码、构建或测试任务仍应用用户已安装的对应 dotnet/skills。

## 长期判断

1. **能力目录应给出可解释的就绪状态。** 文档声明、制品存在、权重就绪、启动成功和质量验收各有证据，不合并为一个 Supported。
2. **诊断必须标明测量范围。** 主应用与独立进程、不同设备的资源计数不能混用；下载耗时也不应算作稳态推理速度。
3. **任务连续性需要保留边界。** 工作区、账号、设备、自动化与授权之间的关系需明确，界面连续不代表所有执行条件未变。

本轮仅向 Local-AI 索引追加一处有新证据的段落，其他研究结论继续保留。
