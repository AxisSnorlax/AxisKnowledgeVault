### P1 — MCP C# SDK 2.4.0：实验性扩展与连接状态边界

[官方发布页](https://github.com/modelcontextprotocol/csharp-sdk/releases/tag/v2.4.0) 显示 11 月 7 日。新增的 `ModelContextProtocol.Extensions.Skills` 明确为实验性；同版防止 `server/discover` 探测提前提交协商版本，修复取消被误报成缺少 OAuth 元数据，并保留刷新时的 canonical resource 与未被替换的 refresh token。

[仓库包说明](https://github.com/modelcontextprotocol/csharp-sdk) 区分 Core、Hosting、ASP.NET Core，以及 Apps／Skills／Tasks 扩展；Skills 面向带可验证文件清单的传递。文档站本轮未返回可用正文，因此不凭接口名称补写未知 API 用法。

对 [[AxisAgent]] 的推论：包版本、扩展成熟度与服务端能力分别记录；探测结果不能直接变成会话最终状态；传输停止、用户取消与鉴权失败保持可区分。文件完整性检查仍不能替代来源信任及运行权限。这些是待验证的集成约束，已补入 [[DotNet]]，没有升级现有项目。

### P2 — Astryx：项目版本对应的组件知识

[Astryx README](https://github.com/meta/astryx) 将 React 19+ 组件、主题、文档与 CLI 一起提供，整体仍标为 Beta；全局 CLI 在项目内使用项目自身版本。内部使用规模和组件数量是项目自报，本轮未独立验收。

[0.7.11](https://github.com/meta/astryx/releases/tag/v0.7.11) 发布页显示 11 月 7 日，记录触摸 Popover 动画、减弱动态效果以及子菜单延迟等细化行为。这是 Web 组件库，不是 WinUI／WPF／Avalonia 的可直接替换组件。

对 Windows/.NET 的设计借鉴：Agent 查询组件时应绑定目标包版本和输入方式；鼠标悬停、触摸、键盘焦点与减少动画偏好分别建模。复用的是组件知识和交互验收方法，不据此迁移 UI 技术路线。

### P3 — HA-MCP：让领域核心校验引用

[ha-mcp v9.1.2](https://github.com/homeassistant-ai/ha-mcp/releases/tag/v9.1.2) 发布页显示 11 月 8 日，修复重复商店条目，并通过组件向 Home Assistant Core 检查 automation、script、scene 引用。[当前 README](https://github.com/homeassistant-ai/ha-mcp) 同时明确服务器代表哪个管理员账户执行，以及客户端连接方式的配置。

工程推论：Agent 工具的参数形状正确不代表领域对象引用有效；应让领域核心提供检查结果，并区分客户端身份与服务器实际执行身份。沿用 [[Professional Software Agent Surface]] 和 [[Agent Capability Policy Enforcement]] 的已有约束。本轮未连接 Home Assistant 或操控设备。

## 本地 AI — OOOSplat 的重试回执与实际配置

[OOOSplat README](https://github.com/ooolabdev/ooosplat) 描述本机 FFmpeg／COLMAP／Brush 流程，并区分 main 功能与安装包。发行列表中的 [0.7.1](https://github.com/ooolabdev/ooosplat/releases/tag/0.7.1) 显示 10 月 28 日，标为 **Pre-release**，不是稳定版。

发布说明规定显存不足时最多重试一次，使用失败进程最后可信点数的 80% 作为上限而不降训练分辨率；缺少可信计数或无法有效降低时直接报错。只有实际重试后才显示相应完成标记。补拍写入独立派生项目，原模型初始化也不等于完整优化器断点恢复。以上是上游行为声明，本轮未运行重建或测量质量。

对 [[AxisAIManager]] 的推论：保存原始失败、重试原因、初始／最终参数及产物来源。兼容回退、质量降级与原任务成功分开标注；取消某个资源预检门槛不代表内存、磁盘或 GPU 约束消失。现有本地引擎就绪与证据分层已覆盖总体方向，本轮不重复追加 Local-AI 索引。

## Avalonia、WinUI 3 与 WPF

[Avalonia 12.1.6](https://github.com/AvaloniaUI/Avalonia/releases/tag/12.1.6) 发布页显示 11 月 9 日，本轮首次取得该版本证据；此前日报的 12.1.5 采样保留。新记录包括 `Window.Activated` 触发前设置 `IsActive`、使用可见单元格内容作为 TableView 行自动化名称，以及 `BeginDraw` 抛出时释放 Vulkan 设备锁。它们给出了事件内状态、结构化控件识别与异常清理的具体回归场景，已增量写入 [[Avalonia]]。

[WinUI 发行列表](https://github.com/microsoft/microsoft-ui-xaml/releases) 仍列 WinAppSDK 2.6.4 为 Latest；[WPF 发行列表](https://github.com/dotnet/wpf/releases) 仍见 10.0.13 及 9／8 维护线，未取得相较上一轮的新框架记录。各维护线与实验分支分别判断，不把版本号简单排序成统一升级建议。

## 长期判断

1. **SDK 能力按状态和成熟度拆分。** 扩展包存在、服务端发现、协议协商及授权不能合成一个“可用”状态。
2. **UI 可验证性包含事件时序。** 控件可见、自动化名称可读与事件处理时状态一致，需要分别验证。
3. **降级完成保留变更轨迹。** 原配置失败、实际重试和最终配置共同构成成功回执，不能只留一个完成图标。

本轮更新完整日报、DotNet 索引和 Avalonia 索引；两个长期页按顺序逐文件处理，保留既有内容与 frontmatter。
