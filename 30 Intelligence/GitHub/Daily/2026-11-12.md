### P1 — improve：计划是有适用范围的交接产物

[官方 README](https://github.com/shadcn/improve) 描述审计、排序、生成计划、派发执行与复核积压事项的流程。规划角色本身不直接实现代码，执行模式通过单独执行者工作；这种模型分工是项目设计，成本或正确率优势未在本轮测量。[发行列表](https://github.com/shadcn/improve/releases) 当前没有 GitHub Release，不把主分支文本当作已验证的稳定产品版本。

[示例计划](https://github.com/shadcn/improve/blob/main/examples/001-extract-shadow-config-resolution.md) 绑定一个历史 commit、代码摘录、范围、验证步骤和停止条件，并明确示例代码已演进。若相关文件变化，要重新对照现场代码；它不是可直接在任意当前仓库执行的通用脚本。

对 [[AxisAgent]] 的推论：Handoff 中的计划保留基线、依赖和可验证的完成判据，执行前确认仍适用；计划状态与实现／测试证据分开。补充到 [[Agent Memory and Knowledge Lifecycle]]。本轮仅将外部技能及示例作为研究资料，没有安装该技能、派发执行或沿用其命令操作本仓库。

### P2 — SourceGit：完整对象身份与平台凭据存储

[SourceGit README](https://github.com/sourcegit-scm/sourcegit) 描述 Windows／macOS／Linux Git GUI 与 AI 提交说明等能力。[v2026.24](https://github.com/sourcegit-scm/sourcegit/releases/tag/v2026.24) 发布页显示 11 月 9 日，修复通过完整 refname 推送分支，避免同名 tag 产生歧义；增加 `git am` 进行中提示，并处理关闭时取消命令的日志更新。

同版将 AI 服务 API key 存入系统凭据库，Windows 使用 Credential Manager；发布说明要求已有 AI 服务重新配置 key。维护者同时表示正在沟通交接，不能从这份公告断言新维护者已经确定。本轮未安装 SourceGit、读取或修改用户凭据。

Windows/.NET 借鉴：显示名称、完整 Git 引用和对象身份分开；取消、进行中和完成状态应反映真实进程结果。配置文件迁移与机密存储迁移也需要分别提供可诊断状态，不将 UI 配置存在等同凭据可用。

### P3 — Unity MCP：重连与 domain reload 保留任务语义

[v10.3.0](https://github.com/CoplayDev/unity-mcp/releases/tag/v10.3.0) 发布页显示 10 月 4 日，是本轮复核的既有发行：包含抑制 broker 重发造成的重复执行、重连前刷新端口发现、让编译等待跨 domain reload 可观察，以及重载后恢复测试 job 等修复。

对 Windows/.NET 专业工具的推论：连接恢复、Editor 重载和任务完成分别表示，状态回取优先复用既有 job 身份。一次 broker 去重修复并不证明所有外部副作用具备 exactly-once 保证。既有 [[Deterministic Agent Runtime]] 与 [[Durable Agent Runtime Identity]] 已覆盖总体方向，本轮不重复追加。

## 长期判断

1. **计划是会过期的交接材料。** 基线、范围、依赖、失效条件和执行证据各自保留，不能将计划文字当作完成状态。
2. **对象身份不能用显示名代替。** Git ref、Editor job、执行环境和模型构建都需要明确归属。
3. **恢复优先核对已发生的事实。** 重连或重发不是重新执行副作用的充分理由，后端新能力也需按实际构建验证。
