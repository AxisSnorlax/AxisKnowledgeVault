# GitHub Trending — 2026-09-09

## 今日结论

Agent 生态的主线已经从“模型 + Prompt + Tool”进一步转向 [[Agent Harness]]、[[Skills]]、[[Context Engineering]]、[[Memory]]、[[MCP]] 与 Browser/Computer Use 的工程化组合；真正的竞争点正在变成如何让 Agent 稳定完成真实工作。

## 值得关注

### openai/skills

- 方向：Agent Skills
- 趋势信号：当前 GitHub Trending 持续出现，说明 Skills 正在从零散 Prompt 演化为正式能力抽象层。
- 为什么值得看：它代表 Agent 能力复用、分发、组合与约束的一种更标准化方向。
- 对 [[AxisAgent]] 的借鉴：建议建立 `Skill Registry + Skill Manifest + Skill Loader + Permission`，不要把所有能力继续塞入通用 Service。
- 关联：[[Agent]]

### mksglu/context-mode

- 方向：Context Engineering / Session Memory
- 趋势信号：近期增长明显，且与 Coding Agent 的高 Token 成本和工具输出膨胀直接相关。
- 为什么值得看：行业重点正在从“扩上下文窗口”转向“减少无价值上下文”。
- 对 [[AxisAgent]] 的借鉴：将 Context Manager 升级为一级 `Context Engine`，负责预算、压缩、工具输出裁剪、Session Memory、Workspace Context 与 Retrieval。
- 关联：[[Agent]] · [[Local-AI]]

### browser-use/browser-use

- 方向：Browser Agent
- 趋势信号：长期保持高热度，Browser 已成为 Agent 真实执行能力的重要入口。
- 为什么值得看：Agent 正从纯 API Tool Calling 进入浏览器和桌面真实环境。
- 对 [[AxisAgent]] 的借鉴：Browser Runtime 应作为独立能力域，与 Search、Computer、Terminal、Files、Git 并列，而不是隐藏在单一 ToolService 中。
- 关联：[[Agent]]

### ChromeDevTools/chrome-devtools-mcp

- 方向：MCP + Browser / DevTools
- 趋势信号：TypeScript Trending 中持续活跃。
- 为什么值得看：MCP 正在成为 Agent 与专业工具、浏览器、IDE 等外部环境之间的标准连接层之一。
- 对 [[AxisAgent]] 的借鉴：MCP Runtime 需要支持连接生命周期、能力发现、权限、超时、断线恢复与工具命名冲突治理。
- 关联：[[Agent]]

### NousResearch/hermes-agent

- 方向：Agent Runtime
- 趋势信号：Python Weekly 中保持较强增长。
- 为什么值得看：更完整的 Agent Runtime 比单一聊天代理更接近长期架构方向。
- 对 [[AxisAgent]] 的借鉴：重点研究 Agent Loop、Tool Execution、Memory、Planning、Subagent 与失败恢复边界。
- 关联：[[Agent]] · [[Local-AI]]

### affaan-m/ECC

- 方向：Agent Harness
- 趋势信号：近期 Trending 增长显著。
- 为什么值得看：Harness 正在成为模型之上的关键工程层。
- 对 [[AxisAgent]] 的借鉴：Agent Runtime 应统一承载 Skills、Context、Tools、MCP、Memory、Approval、Checkpoint，而不是继续演化成多个互相交叉的 Manager。
- 关联：[[Agent]]

### ruvnet/ruflo

- 方向：Multi-Agent / Harness / Memory / RAG
- 趋势信号：TypeScript 生态中持续高热度。
- 为什么值得看：Multi-Agent 没有消失，但正在从 Demo 走向统一调度、Memory 与 Runtime 工程化。
- 对 [[AxisAgent]] 的借鉴：未来可以支持 Specialized Subagents，但应由单一 Runtime 调度，避免多个 Agent 各自持有重复基础设施。
- 关联：[[Agent]]

### microsoft/markitdown

- 方向：文档转换 / Agent 数据入口
- 趋势信号：近期 Trending 增长强。
- 为什么值得看：高质量文档归一化是 Context Pipeline 的基础问题，而不是边缘功能。

### CoplayDev/unity-mcp

- 方向：C# / MCP / 专业桌面软件集成
- 趋势信号：C# Trending 中较有代表性。
- 为什么值得看：C# 的 AI 机会不一定在模型侧，而更可能在 Windows、专业软件和 Agent 接入传统工具链。
- 对 [[AxisAgent]] 的借鉴：Windows/.NET Agent 可以优先深挖 IDE、SCADA、工程软件、桌面程序与 MCP/Tool Runtime 的结合。
- 关联：[[DotNet]] · [[Agent]]

## 趋势变化

1. [[Skills]] 从“提示词集合”向可复用能力层演化。
2. [[Context Engineering]] 明显升温，减少无效 Token 比单纯增加 Context Window 更重要。
3. Browser / Computer Use 持续成为 Agent 的核心执行面。
4. Multi-Agent 正从概念 Demo 收敛到统一 Runtime / Harness。
5. C#/.NET 在 GitHub AI Trending 中数量不占优，但在 Windows、专业桌面软件、MCP 集成层存在明显差异化机会。
6. Desktop 并未因 AI 而边缘化，反而因本地 Agent、Local-first、Computer Use 重新变得重要。

## 对 AxisAgent 的可执行事项

- [ ] 将 Skills 设计为一级模块，并定义 Manifest、Registry、Loader、Permission。
- [ ] 将 Context Manager 重构为 Context Engine。
- [ ] 将 Browser、Computer、Terminal、Files、Git 作为独立 Runtime 能力域。
- [ ] 统一 MCP 生命周期、权限与断线恢复。
- [ ] 设计 Streaming Event Pipeline，避免逐 token 直接触发 UI PropertyChanged。
- [ ] 评估 WinUI 3 桌面端作为 Windows-only Agent 的主 UI 技术路线。
