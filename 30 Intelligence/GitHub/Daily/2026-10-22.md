### P1 — Graphify：每条关系要能追溯其产生方式

官方 README 区分从源码直接提取的 `EXTRACTED` 关系与解析得到的 `INFERRED` 关系；代码路径采用本地 AST 解析，而文档/媒体的语义处理可使用模型。图文件记录 schema 和生成工具版本。[README](https://github.com/Graphify-Labs/graphify)。

[v0.9.93 发布页](https://github.com/Graphify-Labs/graphify/releases/tag/v0.9.93) 显示 10 月 20 日，列有 C# delegate 解析、Obsidian 相对链接及部分读取文件恢复的修复，并变更 AST 缓存 schema。这是已发布版本的复核，不写成今天新发布。

对 Windows/.NET 的设计推论：图中的节点与边应保留来源位置、源码版本和提取器版本；不能把有图、有连接当作 C# 语义解析完整或运行时行为得到证明。反射、生成代码、条件编译等是否覆盖，仍需针对具体项目核对。这些不是本轮已实现或实测的能力。

### P2 — Cloudflare：保持证据覆盖与结论状态分离

官方资料将桌面驱动、Sandbox SDK/运行环境和评估工具分开，并说明后台输入能力取决于平台与目标应用。对 Windows，不能从一个跨平台入口推导全部操作都无需焦点，或驱动连接成功就表示隔离与任务正确性通过。[README](https://github.com/trycua/cua)。
