# GitHub Trending — 2026-09-11

## 今日结论

今天最重要的变化有四条：

1. **Agent Skills 正从“仓库里的 SKILL.md”继续走向跨 Agent 的包管理/分发层。** `vercel-labs/skills` 已把安装、查找、更新、删除、私有仓库和多 Agent 适配做成统一 CLI。
2. **Memory 开始从单 Agent 会话能力走向跨 Harness / 跨供应商交接。** `akitaonrails/ai-memory` 直接把 Claude Code、Codex 等不同 Agent 的会话连续性作为产品问题处理。
3. **Provider 不再只是配置列表，正在出现独立 Routing Plane。** `OmniRoute` 把配额、成本、延迟、上下文、缓存和 fallback 等策略提升到模型调用之前的路由层。
4. **Windows 原生 UI 与专业桌面软件没有被 AI 热潮淘汰。** C# 榜的 `Files`、周榜的 WinUI 3/.NET 10 `tubatools` 仍有明显增长；另一方面 Rust/Tauri/原生工具把 AI/MCP 越来越深地嵌入数据库、CAD、PCB 等专业软件。

## 今日值得关注

### Tencent/teamai-cli

- 方向：Team Harness / Skills Distribution / Shared Context
- GitHub Trending：**+837 stars today**；昨日知识库记录为 +563/day，增长进一步加速。
- 仓库：https://github.com/Tencent/teamai-cli
- 为什么值得看：它继续验证团队 Agent 能力不应散落在个人 Prompt/Skill 目录，而需要 Git 版本化、Review、分发、Recall 和 Prune。
- 对 [[AxisAgent]] / [[Axis Knowledge Vault]] 的借鉴：维持 `Capture → Review → Promote → Recall → Prune`，并把 Skill/Rule/MCP/Knowledge 都纳入来源与版本治理。
- 关联：[[Agent Harness]] · [[Skills]] · [[Memory]] · [[Context Engineering]]

### vastsa/PI-Desktop

- 方向：Local-first Agent Desktop
- GitHub Trending：**+636 stars today**；昨日记录为 +393/day，明显加速。
- 仓库：https://github.com/vastsa/PI-Desktop
- 为什么值得看：独立 Agent Desktop 作为产品类别继续增强，而不是只依附 IDE/CLI。
- 对 [[AxisAgent]] 的借鉴：继续坚持 UI / Privileged Host / Agent Runtime 的边界；Permission、Secrets、Filesystem、Plugin Sandbox、Session Recovery 不应退化成 UI 层能力。
- 关联：[[Agent]] · [[Desktop UI]]

### diegosouzapw/OmniRoute

- 方向：AI Gateway / Provider Routing Plane / MCP / A2A
- GitHub Trending：**+591 stars today**。
- 仓库：https://github.com/diegosouzapw/OmniRoute
- 项目当前声明支持 352 个 Provider，并提供多种 routing strategy、quota-aware fallback、MCP/A2A/REST 等入口；具体规模属于项目自身声明，需要按实际代码和测试验证。
- 为什么值得看：真正值得关注的不是 Provider 数量，而是它把 `模型选择` 与 `路由策略` 分开。成本、配额、延迟、上下文长度、健康状态、Prompt Cache、最近成功路径都可以成为路由因素。
- 对 [[AxisAgent]] 的借鉴：Provider Registry 之外建议预留独立 `Routing Policy` / `Provider Router`，但不要把完整 Gateway 逻辑无条件搬进客户端；先从模型能力、健康、成本、延迟和本地/云偏好五类信号开始。
- 关联：[[Agent]] · [[Local-AI]] · [[MCP]]

### vercel-labs/skills

- 方向：Agent Skills Package Manager / Distribution
- GitHub Trending：**+175 stars today**，总星约 31k。
- 仓库：https://github.com/vercel-labs/skills
- 为什么值得看：CLI 已支持 OpenCode、Claude Code、Codex、Cursor 等 75+ Agent，支持 Git/GitHub/GitLab/本地路径/私有仓库，并提供 add/use/list/find/update/remove/init。
- 趋势判断：`Skill` 正从静态文件格式走向完整的 **Discovery + Install + Scope + Update + Remove + Compatibility** 生命周期。
- 对 [[AxisAgent]] 的借鉴：Skill Registry 不应只做目录扫描；未来需要 Source、Version、Scope（Project/User）、Update、Integrity、Compatibility、Permission 等元数据。
- 关联：[[Skills]] · [[Agent Capability Packaging]]

### akitaonrails/ai-memory

- 方向：Long-term Memory / Cross-Agent Handoff
- Rust Trending：**+237 stars today**。
- 仓库：https://github.com/akitaonrails/ai-memory
- 为什么值得看：它支持通过 MCP + Hooks 接入多个 Agent，记录 prompt/tool/session boundary，并在下一会话提供 handoff；还允许同一 workstream 从 Claude 切到 Codex 等不同 Harness 继续。
- 趋势判断：Memory 正从“一个 Agent 的向量库”变成可独立部署、跨 Harness 的连续性服务。
- 对 [[AxisAgent]] 的借鉴：明确区分 Working Context、Session/Handoff Memory 和长期 Knowledge；不要把三者混成一个 `MemoryService` 或一个向量库。
- 关联：[[Memory]] · [[Context Engineering]] · [[Agent Memory and Knowledge Lifecycle]]

### nashsu/llm_wiki

- 方向：Persistent Knowledge / Incremental Ingestion
- TypeScript Trending：**+94 stars today**。
- 仓库：https://github.com/nashsu/llm_wiki
- 为什么值得看：它不是每次查询都从原始文档重新 RAG，而是增量建立并维护持久 Wiki；还使用 SHA256 增量缓存跳过未变化来源。
- 对 [[Axis Knowledge Vault]] 的借鉴：Vault 的定位应该是“Promoted Knowledge”，不是聊天原始日志。来源变化检测、增量更新、可追溯链接比盲目重新 embedding 全库更重要。
- 关联：[[Memory]] · [[Agent Memory and Knowledge Lifecycle]]

### AlexsJones/llmfit

- 方向：Local AI Hardware Fit / Benchmark / Deployment Planning
- Rust Trending：**+247 stars today**。
- 仓库：https://github.com/AlexsJones/llmfit
- 为什么值得看：它检测 CPU、RAM、GPU/VRAM/后端，按 memory fit、speed、quality、context 对模型评分，并提供 JSON、REST API 与真实 benchmark。
- 对 [[AxisAIManager]] 的借鉴：本地模型管理不应只展示“模型能否加载”，未来可增加 `Hardware Profile → Fit Score → Estimated/Measured TPS → Recommended Context/Quantization`，且估算值必须和实测值明确区分。
- 关联：[[Local-AI]] · [[AxisAIManager]]

### JustVugg/colibri

- 方向：Local MoE / VRAM-RAM-NVMe Multitiering
- GitHub Trending：**+130 stars today**，总星约 27.4k。
- 仓库：https://github.com/JustVugg/colibri
- 为什么值得看：项目把 VRAM、RAM、NVMe 视为统一权重层级，按路由热度缓存/预取 MoE Experts；Windows 有预编译/原生路径，并明确把真实吞吐、TTFT、内存和质量一起测量。
- 对 [[AxisAIManager]] 的借鉴：长期可把 `Memory Tier / KV / Model Residency / Storage Bandwidth` 纳入硬件诊断，但这是实验性路线，不能替代 llama.cpp 主路径，除非真实 benchmark 证明收益。
- 关联：[[Local-AI]]

## Windows / .NET / Desktop 专项观察

### files-community/Files

- C# Trending：**+208 stars today**。
- 仓库：https://github.com/files-community/Files
- 项目标签明确包含 .NET、Fluent、WinAppSDK、WinUI、XAML。
- 借鉴意义：它仍然是现代 Windows 原生桌面 UI 的高价值参考之一，特别适合研究 Navigation、文件列表、上下文菜单、主题、窗口行为和 Windows Shell 集成。
- 对 [[AxisAgent]]：若继续评估 WinUI 3，不应只看官方 Gallery，应把成熟真实应用的布局、交互和资源组织纳入 UI Benchmark。

### luolangaga/tubatools

- C# Weekly Trending：**+686 stars this week**。
- 仓库：https://github.com/luolangaga/tubatools
- 当前 README 明确为 **WinUI 3 + .NET 10** 社区重构版，并包含 Fluent 原生工具体系和 AI 助手。
- 借鉴意义：这是比 Demo 更接近“复杂 Windows 工具工作台”的 WinUI 3 实例。尤其值得观察其卡片、导航、硬件监控、快速模式（关闭动画）和工具密集型布局。
- 对 [[AxisAgent]]：如果后续做 UI Framework Qualification，可把它作为 WinUI 3 真实应用参考之一，但不能仅凭 Star 数判断性能和维护质量。

### CoplayDev/unity-mcp

- C# Weekly Trending：**+239 stars this week**。
- 仓库：https://github.com/CoplayDev/unity-mcp
- 趋势意义：再次确认 C#/.NET 的 Agent 机会主要在 **专业软件能力暴露**，不是复制 Python Agent Framework。
- 对 Axis 产品：SCADA、Protocol Studio、工程工具将来更适合暴露受控 MCP/Tool Surface，而不是把 AI 逻辑硬塞进每个 UI 页面。

### t8y2/dbx

- Rust Trending：**+238 stars today**。
- 仓库：https://github.com/t8y2/dbx
- 项目主打约 20 MB、无捆绑 Chromium的跨平台数据库客户端，并把 MCP Server 独立分发；MCP 权限区分 read-only / safe-write / high-risk-write。
- 对 Axis 工业工具的借鉴：专业桌面软件可以保持本体轻量，同时把 Agent 接口作为独立 MCP Surface，并对读、普通写、高风险写做明确权限分层。

### 低星但高度相关：asklar/lvt

- 当前约 24 stars，不属于 Trending 爆点，因此不以热度作为推荐依据。
- 仓库：https://github.com/asklar/lvt
- 价值：能检测/遍历 Win32、WinUI 3、WPF、WinForms、Avalonia、Chromium 等 UI，并通过 MCP 让 Agent inspect/click/type/set-value；读操作与允许输入可分离。
- 对 [[AxisAgent]]：这是 Windows Computer Use / UI Verification 很值得实验验证的工具形态，尤其可用于统一 UIA + framework-native visual tree，而不是只靠截图坐标。

## 与 2026-09-10 相比的趋势变化

1. **Team Harness 与 Agent Desktop 继续加速，而不是一次性 Trending 噪声。** `teamai-cli` 与 `PI-Desktop` 的 daily stars 都较昨日进一步上升。
2. **Skill 生态进入包管理阶段。** `vercel-labs/skills` 把跨 Agent 安装、更新、私有仓库和 scope 做成明确产品能力，强化了昨日的 `Skill → Plugin → Harness` 分层判断。
3. **Memory 的边界更清楚。** `ai-memory + llm_wiki + context-mode + teamai-cli` 共同指向：Working Context、Session Handoff、Long-term Knowledge 应分层治理。
4. **Provider Routing 成为独立问题。** `OmniRoute` 是今天较强的新信号；先跟踪，不立即把其庞大 Gateway 范式视为 AxisAgent 必需架构。
5. **本地 AI 从“能跑哪个模型”走向硬件适配与分层内存调度。** `llmfit` 偏工程规划，`colibri` 偏实验性运行时，两者都强调真实硬件测量。
6. **WinUI 3 / 原生 Windows 工具仍有增长，但 WPF/Avalonia 今日没有足够明显的新趋势变化。** 因此本日不机械修改 Avalonia 长期索引。
