## P1 — Rig：摘要替换范围不能在提交时扩大

[Rig v0.47.0](https://github.com/0xPlaygrounds/rig/releases/tag/v0.47.0) 页面显示 11 月 20 日，包含破坏性 API 变化。[已合并的 #3436](https://github.com/0xPlaygrounds/rig/pull/3436) 说明，摘要应用时核对会话前缀仍是生成时捕获的消息：随后新增的消息保留，已捕获消息被编辑则拒绝摘要，空摘要也作为失败处理。被替换的原消息仍可在 transcript 中查看；移除 `/uncompact` 不等于删除原始记录。

工程推论：压缩准备、模型生成和摘要提交是三个阶段，提交应携带来源范围及版本条件；模型返回文字不自动授权覆盖最新上下文。新增设计建议写入 [[Agent Memory and Knowledge Lifecycle]]。

[当前 README](https://github.com/0xPlaygrounds/rig) 区分 Rust 库、终端 coding agent 与可选 MCP／本地模型组件；终端 agent 文档列出 Linux、macOS，并明确 main 指南可能领先发行标签。因此这里只向 Windows/.NET 借鉴状态模型，不宣称已验证其原生 Windows agent 或迁移现有实现。

## P2 — last30days：报告捕获与知识晋升分开

[v4.6.0](https://github.com/mvanhorn/last30days-skill/releases/tag/v4.6.0) 页面显示 11 月 22 日，包含完成报告捕获和离线 transcript 回填。[#1556](https://github.com/mvanhorn/last30days-skill/pull/1556) 描述完成边界识别、内容哈希去重、原子写入和保留原始材料；检索可优先展示成稿，原始文件仍保留。捕获依赖本地宿主及 hook 能力，托管界面没有同等本地运行条件。

工程推论：报告被识别为完整、成功归档和内容经核验是不同状态。应保留原材料关联、捕获范围及访问边界，不能将自动入库等同于 verified knowledge。此项延续既有 Capture／Review／Promote 分层，本轮未安装 hook、扫描用户会话或发布任何资料。

## WinUI / .NET — FluentCleaner 从预览到正式构建

[26.11.108](https://github.com/builtbybel/FluentCleaner/releases/tag/26.11.108) 页面显示 11 月 19 日，作者宣布 NativeAOT 构建不再作为预览，并说明设置语言列表曾因一处依赖反射的路径而为空，已在重新上传的制品及本版修复。此处记录该具体缺陷，不把它概括成 NativeAOT 完全不支持反射。

同版把 Mica／Mica Alt／Acrylic 放进设置，展示规则文件位置，并说明用户可将自定义规则放到独立文件。工程推论：首帧成功、包体缩小与低频设置页兼容性应分别验证；发布标签、实际制品及其摘要需要能区分。用户规则与随版本更新的规则也应有明确归属。WinUI 索引补充发布状态，保留 11 月 19 日对旧预览版的历史观察。

作者继续引用的启动时间仍是其自报数据，本轮未独立复测，也未运行清理或系统调整操作。

## WPF — STranslate 的触发与日志边界

[v2.0.12](https://github.com/STranslate/STranslate/releases/tag/v2.0.12) 页面显示 11 月 21 日。UI Automation 取词新增可关闭开关且默认开启；关闭后直接模拟复制。修复还涉及 HTTP／错误日志的凭据脱敏、长按截图翻译快捷键重复触发，以及文本框布局尚未完成时显示替换差异造成的异常。

Windows/.NET 借鉴：用户按键的一次动作、自动重复事件和实际发起的任务分别关联；依赖布局的观察等待就绪状态。日志的正常路径和异常路径都要核对实际输出范围。以上是发布说明支持的研究方向，本轮没有采集剪贴板、截图、凭据或执行 .NET 测试。
