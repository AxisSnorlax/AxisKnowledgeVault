# GitHub Trending — 2026-09-15

## 今日结论

今天最重要的变化不是“又多了一个 Agent Framework”，而是 Agent 工程化继续从 Prompt / Skill 层下沉到更硬的运行约束：**关键步骤由 Deterministic Engineering 保证，Agent 负责动态决策；Runtime 必须能追踪 Tool/MCP 调用、限制凭据暴露并留下可复核证据。**

同时，[[Agent Skill Supply Chain]] 与 [[Local-AI]] 两条已连续多日出现的趋势再次明显加速。

## 值得关注

### alibaba/open-code-review

- 方向：AI Coding / Code Review / Agent Harness
- 今日增长：GitHub Trending 约 **+1,796 stars/day**。
- 项目：https://github.com/alibaba/open-code-review
- 为什么值得看：它明确反对“纯语言驱动 Agent 承担所有流程”，将文件选择、分组、规则匹配、评论定位等不能出错的步骤放到确定性工程逻辑中；Agent 只负责动态判断、上下文检索和推理。
- 对 [[AxisAgent]] 的借鉴：Permission、Approval、Workspace Boundary、Tool Dispatch、Run State、Artifact/Verification Mapping 等必须由代码和状态机保证，不能依赖 Prompt 约束。Agent 应被限制在“选择与推理区”，而不是成为安全边界。
- 长期沉淀：[[Deterministic Agent Runtime]]。

### github/gh-aw（GitHub Agentic Workflows）

- 方向：Agent Workflow / Runtime Observability / Security
- 近期变化：2026-09-14 的官方周报显示一周连续发布 17 个版本，重点是 `gh aw logs` 可观测性、模型路由修复、安全输出与凭据安全。
- 项目：https://github.com/github/gh-aw
- 关键变化：
  - JSON 日志开始记录每次 MCP Tool Call 的时间、Server 和 Tool 名称；
  - 修复自定义 Engine 下的 Threat Detection；
  - Slash-command router checkout 使用 `persist-credentials: false` 缩小 `GITHUB_TOKEN` 暴露窗口；
  - GitHub Actions 进一步固定到 Commit SHA；
  - Repo-memory 并发 merge 时保留 JSONL 行，避免历史被覆盖。
- 对 [[AxisAgent]] 的借鉴：Durable Run Record 不应只存“最终结果”，还应有 Tool/MCP identity、timestamp、permission/approval、credential scope、safe-output、threat/verification 等事件；敏感凭据应按最小生命周期和最小作用域注入。
- 长期沉淀：[[Deterministic Agent Runtime]]。

### Panniantong/Agent-Reach

- 方向：Browser / Internet Capability Routing
- 今日增长：GitHub Trending 约 **+640 stars/day**。
- 项目：https://github.com/Panniantong/Agent-Reach

## 今日长期判断

### 1. Deterministic Engineering × Agent

长期模型建议正式采用：

```text
Request / Task
  ↓
Deterministic Contract
  ├── Scope / Selection
  ├── Permission / Approval
  ├── State Transition
  ├── Integrity / Position Mapping
  ├── Verification Gate
  └── Evidence Recording
  ↓
Agent Decision Zone
  ├── Reasoning
  ├── Retrieval
  ├── Planning
  └── Dynamic Tool Choice (within policy)
```

关键原则：**不能出错的步骤，用代码保证；允许探索的步骤，再交给 Agent。**

详见：[[Deterministic Agent Runtime]]。

### 2. Observability / Security 成为 Runtime 基础设施

Agent Run 至少应具备：

- Tool / MCP Server / Tool Name / Timestamp；
- Correlation / Run / Parent Run；
- Permission / Approval Event；
- Credential Scope / Lifetime；
- Input / Output Digest；
- Safe-output / Threat / Verification Result；
- Artifact / Diff / Log lineage。

这延续了此前 [[Agent]] 中的 Durable Run / Evidence Lineage，但今天已经得到 GitHub 官方工程实践的进一步验证。

### 3. Capability 不等于 Backend

Browser/Search/External Data 能力应抽象为稳定 Capability；具体 Browser、CLI、MCP 或 API 只是可替换 Adapter，并由真实 Health Probe 和 Policy 决定当前路由。

这与 Provider Routing 类似，但应保持独立权限域，避免“模型路由”和“外部能力路由”混成一个巨型 Gateway。
