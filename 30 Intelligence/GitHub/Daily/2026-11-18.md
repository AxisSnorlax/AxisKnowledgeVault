## 今日结论

今天的重点是 **心跳过期、运行终止与资源所有权释放需要分别判定**。LoopForge 0.4.0 收录的修复说明：心跳落库慢不一定代表执行者已停止，旧回合的清理也不能释放新回合已经取得的工作区租约。这为已有取消与队列模型补充了多实例、续租和时钟边界。

Plannotator 则提供 Windows 文件保存失败的具体样本：原子替换失败后保留旧配置，不能继续降级成可能截断原文件的直接写入。C#/.NET 今日复核 Semantic Kernel、optimizerDuck 和 Unity MCP；本地 AI 关注 MiniMind 宣传耗时的实际测量范围。长期页只追加运行时所有权这一增量。

### P1 — LoopForge：迟到的心跳与仍被持有的工作区

[LoopForge README](https://github.com/Tencent/LoopForge) 描述 Agent、脚本、人工确认和子工作流节点，以及平台沙箱和连接的本地执行机器。独立 Local 版当前使用内置工作流；把平台自定义 SOP 导出为独立本地运行仍列为计划，不能把两种形态视作功能完全相同。

[v0.4.0](https://github.com/Tencent/LoopForge/releases/tag/v0.4.0) 页面显示 11 月 17 日，包含 [#810](https://github.com/Tencent/LoopForge/pull/810) 的慢心跳修复。其最终说明保留本进程活跃回合，回收时按原回合的租约身份匹配，并用续期状态保护仍被持有的工作区。**另一副本仍可能把心跳过期的回合记为中断**，该修复并不声称消除了所有多实例误判。

工程推论：运行状态的观测结果不能直接授予下一任务写权限；租约释放应核对具体持有者及当前续期证据。作者提供的验证属于项目自报，本轮未重跑。新增结论写入 [[Deterministic Agent Runtime]]，不因此安装平台或改动现有定时任务。

### P2 — Plannotator：安全保存失败时保留原文件

[v0.28.67](https://github.com/backnotprop/plannotator/releases/tag/v0.28.67) 页面显示 11 月 17 日。配置的临时文件加重命名写入失败时，该版不再回退为直接写 `config.json`；原文件保留并显示失败，`state.json` 同样处理。Windows 上遇到文件被其他程序持有会短暂等待。

同版让关联机器的图片、相邻文件和 HTML 页面可读取，但要求两端均为该版本；复制路径仍是远端机器的路径。本地编辑器不能打开的远端文件不再显示相应入口。代码审查的 diff 加载失败时明确显示错误和重试，不再显示演示 diff。

Windows/.NET 借鉴：保存失败、远端资源身份与真实审查数据缺失都应保留其状态。可见的页面不能代替写入成功，演示内容也不能代替目标代码。这延续 [[Professional Software Agent Surface]] 与 [[Agent Verification and Audit Plane]] 的既有原则。

## 本地 AI — MiniMind 的两小时口径

[MiniMind 当前 README](https://github.com/jingyaogong/minimind) 提供小模型结构、训练与推理教程，并明确其“两小时”对应 **单张 RTX 3090 上 SFT 阶段的一个 epoch**；这是作者自报耗时，不能扩展成任意设备完成全部预训练与对齐流程的时间。

README 的模型表将 minimind-3／minimind-3-moe 记为 2026-04-01；[GitHub Releases](https://github.com/jingyaogong/minimind/releases) 的 latest 是 MiniMind Docs（v2）条目。文档标签与模型权重版本分别核对，不能仅根据 latest 名称认定新权重发布。

Windows/.NET 借鉴：本地 AI 实验回执需记录训练阶段、数据量、epoch、GPU、权重与推理后端。教程可复现性、工具调用格式和实际产品质量分别评价；本轮未下载数据或权重，未测量 Windows 推理性能。
