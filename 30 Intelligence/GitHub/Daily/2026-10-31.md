### P1 — Lightpanda：图片文件不必然是页面视觉证据

[官方 README](https://github.com/lightpanda-io/browser) 说明它是独立实现的浏览器，没有图形渲染引擎；PNG/PDF 导出描述为文本型页面渲染。CDP/BiDi 接入和 DOM 操作可供自动化研究，但不能据此判定 CSS 布局、重叠、字体或交互像素表现已通过真实浏览器验证。

[1.0.2 发布说明](https://github.com/lightpanda-io/browser/releases/tag/1.0.2) 显示 10 月 23 日，列出页面历史隔离、元素坐标、事件路由及 CDP 行为修复。这些记录本身也说明兼容性应按具体能力和版本核对。

Windows 边界同样明确：当前 README 没有原生 Windows 二进制，给出的路径是 WSL2。其性能倍数来自项目自报的指定环境，本轮未复测。对 [[AxisAgent]] 的推论是记录观测引擎、版本、渲染模式和未覆盖项，补充到 [[Agent Verification and Audit Plane]]。

### P2 — CopilotKit/OpenBot：可改造模板与运营完成品分开

[README](https://github.com/CopilotKit/OpenBot) 将其定位为 beta 模板，连接 AG-UI Agent，并集中处理工具目标、权限决定与审计。它是 `CopilotKit/OpenBot`，与 10 月 28 日研究的 `nightly-labs/openbot` 不是同一项目。

文档明确默认单用户配置把请求作为一个管理员处理，多用户可达的部署需另行启用登录；这些是模板的运行前提，不能省略后再宣称开箱具备全部多租户边界。[v0.2.0](https://github.com/CopilotKit/OpenBot/releases/tag/v0.2.0) 显示 10 月 12 日，记录共享连接迁移与共享目录写命令确认规则变化，属于已有版本复核。

对 Windows/.NET 工程的借鉴是保留独立 Gateway/Policy/Audit 合同，而不是按前端会话是否连通判定权限已正确实现。当前资料没有提供用户 Windows 本机的完整部署验收，本轮未创建账户、连接工具或启动该模板。

## 本地 AI — Hex 的平台说明需要细到组件

[README](https://github.com/anomalyco/hex) 介绍本地听写和 Windows x64/ARM64 beta；但 [dev 分支 Windows 文档](https://github.com/anomalyco/hex/blob/dev/docs/windows.md) 同时注明，当前替换后的 Rune 界面尚未在 Windows 上运行，交叉检查不包含完整链接、语音引擎构建或实机执行；Windows 本地转录服务也列为不可用。应保留这些组件限制，不把文档中的 Implemented 或 beta 一概视为端到端可用。

本轮 latest 入口返回 [@kitlangton/hex@0.3.1](https://github.com/anomalyco/hex/releases/tag/@kitlangton/hex@0.3.1)，显示 9 月 26 日，内容是有界 SSE 解析修复。该包标签不能单独确定当前 Windows 桌面制品状态。

对 [[AxisAIManager]]，语音采集、模型后端、界面、粘贴与本地 API 应分别保存验证范围；流式路径和回退路径也不能混成同一个性能结果。沿用 Local-AI 索引已有的就绪分层，本轮不追加重复段落或推荐立即安装。

## 长期判断

1. **证据要标明生成方式。** 文本导出、文本型图片、DOM 状态和图形渲染各有覆盖范围，不能仅凭文件扩展名判定证据类型。
2. **实现、构建和实机运行分别记录。** 平台列表与检查通过不是完整产品资格，缺失组件与未验证路径需显式保留。
3. **模板的前提条件也是合同。** 身份、部署范围和权限默认值需要进入验收，品牌和界面完整度不能代替这些证据。

本轮只向 Agent Verification and Audit Plane 追加浏览器观测后端的证据约束，保留其他长期判断与人工内容。
