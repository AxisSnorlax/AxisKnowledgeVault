## 今日结论

今天的新增工程证据集中在 **异步工具调用的持久化、去重与取消状态**。Infinity / RAP 提供了具体模型，但消息去重不能自动证明外部副作用恰好执行一次，发送取消通知也不能直接标记任务已停止。

Concat 补充了专业编辑器与 MCP 共用引擎、通过项目目录锁避免多个进程同时拥有项目的样本。Quiver 与 Magnitude 则分别带来发行制品匹配和下载恢复的维护记录，值得按真实版本与平台核对。

### P1 — Infinity / RAP：等待工具不必占用整个执行进程

[官方架构文档](https://infinity.hydro.run/docs/infinity-runtime/architecture/) 描述把工具结果等输入统一为消息，按会话分组处理；工具调用的历史记录在派发前提交，稳定 ID 用于处理重复投递，同一会话串行、不同会话并发。

[RAP 规范](https://infinity.hydro.run/docs/rap/spec/overview/) 将长时工具与结果回调分开，并明确取消、会话关闭通知属于 best-effort。对 [[AxisAgent]] 的推论：需要区分已持久化调用、已派发、取消请求、确认停止与结果未知；外部副作用仍需独立幂等或读回机制。这部分补充到 [[Deterministic Agent Runtime]]。

[仓库 latest 入口](https://github.com/hydro-project/infinity/releases/tag/sandbox-remote-v0.2.0) 本轮指向 10 月 22 日的 `sandbox-remote-v0.2.0`。该标签是组件发行，不能作为整个 Runtime 或 RAP 均已达到同一成熟度的证明。并发规模与资源效率为项目自述，本轮没有验证 Windows 宿主资格或容量。

### P1 — Concat：共享编辑命令仍需明确项目所有权

[MCP 文档](https://github.com/jub0t/Concat/blob/main/docs/MCP.md) 将 window 与 headless 模式分开，提供显式选择和模式查询；项目目录锁阻止另一个进程同时打开同一项目，修改需要保存才落盘。文档还明确，Agent 编辑自己的项目，直接实时修改用户窗口中项目的 live mode 仍在计划中，不能把“通过窗口服务”理解为该能力已经交付。

[v0.2.8](https://github.com/jub0t/Concat/releases/tag/v0.2.8) 页面显示 10 月 20 日，记录项目锁、Windows 锁实现、从类型生成请求 schema 及内置 MCP 等变化。对 Windows/.NET 专业工具，可借鉴“同一业务命令 + 明确所有权 + 保存/读回”的分层；既有 [[Professional Software Agent Surface]] 已覆盖总体原则，不重复晋升。

[README](https://github.com/jub0t/Concat) 当前将产品标为 beta，并注明 Windows ARM 构建暂停；本轮未运行其媒体处理或本地 AI 模型，也未改变系统安装策略。

### P2 — Quiver：同一版本标签不一定对应同一发行制品

[v3.5.1](https://github.com/tgeorgiadis/quiver-launcher/releases/tag/v3.5.1) 页面显示 10 月 15 日，本轮复核了上次迁移研究之外的制品选择说明：更新尽量选择与已安装构建相同的资产；无法唯一匹配时由用户选择；滚动标签的资产重新构建也可能构成更新。

对 .NET/Avalonia 应用分发的推论：安装身份应保留来源、资产身份、架构与摘要，不能只有显示版本号。项目的 Verified 标签有自身的来源、等待与扫描定义，不等于保证软件无缺陷或适用于所有机器。本轮未安装或更新任何应用。

## 本地 AI：Magnitude 的恢复与测量条件

[CLI 0.2.14](https://github.com/magnitudedev/magnitude/releases/tag/@magnitudedev/cli@0.2.14) 页面显示 10 月 29 日，记录推理引擎分段下载重试、重启后续传、可见的错误与下次重试时间，以及避免在下载仍推进时按固定启动时限取消。另有针对 OpenCode 不同主版本的启动适配。

同一说明把模型目录的 Fastest 排序定义为机器上 **50K context 的速度估计**，不是每个模型都已实测。对 [[AxisAIManager]]，下载进度、启动就绪与推理测量继续分层；进度时限、无进展时限与用户取消需要分别设计。已有 Local-AI 合同能容纳这些观察，本轮不重复追加索引。

[README](https://github.com/magnitudedev/magnitude) 的倍速与硬件支持是项目声明；发行记录中的 CPU 改善也绑定特定模型和机器。本轮不将其推广为用户 Windows GPU 或全部模型的实际收益。

## 长期判断

1. **消息去重与外部效果分开。** 会话内部重投递处理，不自动保证文件、设备或服务调用只发生一次。
2. **取消是需要证据的状态转换。** 已请求取消、已停止和无法确认必须可区分，迟到结果也要关联原调用。
3. **平台、模式与制品身份明确记录。** 项目支持名单、MCP 模式和版本号都不能替代实际拥有的资源与部署资产。

本轮只向 Deterministic Agent Runtime 增加一处异步调用状态补充，其他长期页保留既有内容。
