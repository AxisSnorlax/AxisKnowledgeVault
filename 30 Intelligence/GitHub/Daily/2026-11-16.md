### P1 — Univer：先提交草稿，再保存文档

[Univer README](https://github.com/dream-num/univer) 将内容模型、命令、计算和 Facade API 与 UI 插件分开，Agent 可以使用相同应用 API。仓库中的 Apache-2.0 核心与商业 Web／Server／AI 扩展分别分发，演示范围不能全部算作默认开源安装能力。

[v1.5.0](https://github.com/dream-num/univer/releases/tag/v1.5.0) 发布页显示 11 月 14 日。其 Slides 自定义保存说明要求先等待 `endTextEditingAsync()` 返回 true；false 表示草稿未能提交或 IME composition 尚未结束。该接口位于 `@univerjs-pro/slides-ui/facade`，这里明确记录其 Pro 扩展范围。

对 [[AxisAgent]] 和 Windows/.NET 专业软件的推论：屏幕中可见文本、已提交的领域模型和持久化版本分别取证；草稿提交失败时保留草稿及原因，不能仅凭保存函数返回就确认用户刚输入的内容已落盘。具体补充到 [[Professional Software Agent Surface]]，本轮未操作用户文档或接入 SDK。

### P2 — AG-UI：无调用身份的事件不能冒充完整结果

[2026-11-13 发布记录](https://github.com/ag-ui-protocol/ag-ui/releases/tag/release/2026-11-13) 本轮发布的是 `@ag-ui/langgraph 0.0.46`：读取原生 interrupt response schema、展开序列化的 ToolMessage 输出，跳过缺少 tool call id 的结束输出，并在 `RUN_STARTED` 声明 protocolVersion。相关 client peer 依赖提升至 >=1.0.0。

这是适配器的发行与兼容性信息，不意味着整个 AG-UI 项目所有包都使用同一版本。工程推论：事件格式、适配器版本与调用关联要一并核对；某个输出没有形成合法事件，不能据此推断底层工具从未执行。沿用 [[Agent Verification and Audit Plane]] 的证据充分性要求，不重复追加。

### P3 — Bombadil：失败需要保留可缩减的轨迹

[Bombadil](https://github.com/antithesishq/bombadil) 面向 Web 和终端 UI 的属性测试。[v0.7.10](https://github.com/antithesishq/bombadil/releases/tag/v0.7.10) 发布页显示 10 月 21 日，增加浏览器／终端驱动的 `shrink` 命令、动作生成器组合及 trace／截图记录；`fuzz` 命令仍标为 experimental。

对 UI 验证的借鉴：保留触发失败的动作序列和终止状态，再缩减成可复核案例；属性、生成器和探索范围共同限定结论。没有找到失败不能证明覆盖所有交互。此处是方法观察，不宣称它已支持原生 WinUI／WPF 窗口；本轮未生成或运行 UI 测试。

## C#/.NET — UniGetUI 的多后端就绪状态

[UniGetUI README](https://github.com/Devolutions/UniGetUI) 描述面向 Windows、同时提供其他平台构建的多包管理器 GUI。[v2026.3.4](https://github.com/Devolutions/UniGetUI/releases/tag/v2026.3.4) 发布页显示 11 月 13 日，新增显示各管理器最近成功／失败的 Health 页面，以及默认关闭的 Agent Skills 扩展。

同版让启动时更新检查等待各包管理器的已安装列表，修复把另一份较新安装误判为可更新等问题；.NET Tool 使用用户 NuGet 配置中的源，pip 不再操作其他应用所属的 Python 环境。发布说明还记录下载安装器的 hash 校验与签名者展示。

Windows/.NET 借鉴：管理器可调用、库存已就绪、更新判定、实际安装和修复动作分别建模；包身份带上来源与安装范围。最近一次成功不能无限期当作当前健康，出现可选技能扩展也不自动授权安装。本轮未运行包管理器或读取私有源凭据。
