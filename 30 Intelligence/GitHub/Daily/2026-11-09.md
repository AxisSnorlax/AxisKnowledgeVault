### P1 — OpenBitFun：控制视图与执行身份分开

[官方 README](https://github.com/GCWing/OpenBitFun) 区分多设备工作台、手机控制端和 SSH／容器工作区：控制端断开或切换视图不等于宿主机任务停止。[v1.0.9](https://github.com/GCWing/OpenBitFun/releases/tag/v1.0.9) 发布页显示 11 月 5 日，新增多设备工作台，并记录 SSH 恢复、远程搜索、项目 Hooks 和设备会话路由等变化；nightly 另列为预发布，不能与该稳定发行混用。

[当前远程工作区文档](https://github.com/GCWing/OpenBitFun/blob/main/docs/features/remote-workspaces.md) 说明命令和文件操作指向所选 SSH／容器／WSL 环境，Runtime 与会话资料仍在 OpenBitFun 宿主机。远程会话 fork 共享工作树，不会自动创建 Git worktree；断开后能显示某次已存 diff，也不意味着完整回滚覆盖已成立。

对 [[AxisAgent]] 的推论：任务回执保存宿主机、执行目标、工作区和产物归属；恢复时重新核对绑定，不能拿控制端同名文件替代远端成果。本轮补入 [[Durable Agent Runtime Identity]]。这是文档研究，未部署 OpenBitFun、连接其他设备或改变用户环境。

### P2 — Concat：导出结束、取消与格式兼容性

[Concat v0.2.9](https://github.com/jub0t/Concat/releases/tag/v0.2.9) 发布页显示 11 月 5 日，相比本库此前记录的 0.2.8，有新的发行证据：退出时取消导出并通知调用方、清理临时文件；0.2.9 保存后的项目由 0.2.8 明确拒绝打开，以免静默丢失新字段。Windows 部分还记录 shader 编译器定位、软件图形入口及保留文件名处理。

[MCP 文档](https://github.com/jub0t/Concat/blob/main/docs/MCP.md) 继续区分 window／headless 模式与项目锁，修改在 `project_save` 前仍驻留内存；实时编辑用户窗口中项目的 live mode 仍标为计划，不能误报已交付。

Windows/.NET 借鉴：长任务退出合同要覆盖取消结果与临时产物归属；保存版本和最低读取版本应明确。旧客户端拒绝新格式与可回滚到旧格式是两件事。导出成功仍需核对目标文件、媒体时长和解码结果，不只依赖 UI 状态。发布说明中的性能提升属项目自报，本轮未测量。

### P3 — agent-browser：配置变化不应意外替换会话

[v0.41.2](https://github.com/vercel-labs/agent-browser/releases/tag/v0.41.2) 发布页显示 11 月 3 日，本轮复核到超时参数变化导致会话重启、裸 `open` 丢失 profile／浏览器参数、Windows 用户目录识别等修复；还支持按需加载单个技能参考资料。

对 AI Coding 与桌面工具宿主的推论：会话标识、启动配置、默认超时和单次等待设置分层；操作结果带回实际会话身份。引用文件按需加载可控制上下文体积，但引用内容的版本与适用条件仍要保存。本轮没有启动浏览器自动化或修改本机 profile。

## 长期判断

1. **运行身份包含环境归属。** 控制端、Runtime 宿主、工具目标、路径命名空间和产物来源都应明确。
2. **恢复能力按证据声明。** 会话分叉不自动提供文件隔离，历史 diff 可读也不自动保证完整回滚。
3. **交付合同按版本和平台限定。** 支持 MCP、保存项目或安装模型，都不足以单独证明所有功能已可用。

本轮只更新日报及 Durable Agent Runtime Identity 的一个日期段落，复用已有取消、验证与能力分层原则。
