## WinUI / .NET — 框架版本与应用制品分别验证

### Windows App SDK 2.7.0：DPI、关闭过程和 AI 状态

[WinUI 发行页](https://github.com/microsoft/microsoft-ui-xaml/releases/tag/winui3%2Frelease%2F2.7.0) 与 [Microsoft Learn 稳定通道说明](https://learn.microsoft.com/en-us/windows/apps/windows-app-sdk/release-notes/windows-app-sdk-2-0?pivots=stable#version-270) 均记录 2.7.0，发布日期为 11 月 17 日。今天是本轮新增观测日，不将它写成 11 月 19 日发布。

WinUI 修复包括 `CompositionEngineType.System` 下 DPI-aware 应用的输入偏移、空文本控件获得焦点时的文本光标指示，以及 XAML 线程退出后从后台线程读取 `Window.DispatcherQueue` 的崩溃。

Learn 说明还列出 `LanguageModel` 的模型名／版本及 LoRA 兼容状态，以及显存不足、Game Mode 阻断的独立响应状态；模型身份与详细兼容信息能否取得，取决于实际安装的 AI 组件。工程推论：包版本、设备和组件就绪状态分开记录，不能从 API 存在推断任何机器都可完成推理。

### FluentCleaner 26.11.99：原生构建是候选样本

[26.11.99](https://github.com/builtbybel/FluentCleaner/releases/tag/26.11.99) 页面显示 11 月 17 日。作者明确将此 NativeAOT 构建称为 preview，并说明设置及应用清单读取改用生成代码；移除了该应用未使用的 AI 依赖，提供 x64／ARM64 发布配置。Modern WinUI 3 与 Classic WinForms 是两个独立构建，不能混算包体或运行要求。

作者报告同机窗口显示耗时由 347 ms 降至 126 ms；未提供本轮独立复测。这一结果同时涉及编译方式和依赖裁剪，不能把所有变化都归因于 UI 框架。对 Windows/.NET 的借鉴：先按实际制品核对配置兼容、应用清单、架构和关键交互，再讨论冷／热启动与内存收益，不从一次首帧数据推导整个产品已经完成 AOT 资格验证。

## WPF — STranslate 的原文与请求文本

[STranslate v2.0.11](https://github.com/STranslate/STranslate/releases/tag/v2.0.11) 页面显示 11 月 17 日。翻译前替换支持规则排序和草稿测试，界面及历史记录可显示差异、预览并按服务复制实际发送文本；选中文本优先通过 UI Automation 获取，失败再回退模拟复制。

同版修复不同缩放比例副屏的图片翻译窗口位置／尺寸，以及模拟复制粘贴意外触发目标应用 Alt 菜单的问题。工程推论：用户输入、规则变换、服务请求和返回结果应有明确关联；输入获取路径和 DPI 环境属于复现上下文。这里记录发布说明中的行为，本轮没有读取用户剪贴板或向翻译服务发送内容。

## 本地 AI — OpenVINO 的输入形状和后端组合

[OpenVINO 2026.4.1](https://github.com/openvinotoolkit/openvino/releases/tag/2026.4.1) 是本轮 latest 返回的既有版本，页面显示 10 月 1 日。官方记录修复动态形状下、模型输出带 transpose 时远端零拷贝 tensor 的错误结果，并修复滑动窗口 KV-cache 的索引及低精度形状问题。

Windows NPU 修复明确限定部分 Core Ultra Series 3 与驱动组合；CPU 的 ISA 上限也有发布构建及内核选择修复。对本地推理的借鉴：记录模型／量化格式、形状、输出内存方式、设备和驱动组合，检查结果正确性后再比较速度。不能从“模型加载成功”或某个后端可用推断所有动态输入正确；本轮未下载模型、升级驱动或运行硬件测试。

[WPF 发行列表](https://github.com/dotnet/wpf/releases) 仍可见 10.0.15 及 9.0.23／8.0.34 维护线；[Avalonia 列表](https://github.com/AvaloniaUI/Avalonia/releases) 为 12.1.6 与 11.3.23 维护线。本轮没有需要追加这两类框架索引的新证据。WinUI 的 2.7.0 按稳定发行单独记录，保留此前 2.6.6-experimental 的通道区别。

## 长期判断

1. **新增到 WinUI 索引**：将 NativeAOT 应用制品、依赖裁剪和框架版本分别记录，并把 DPI 输入命中与窗口关闭后的访问纳入候选验证范围。这里提出后续研究方向，没有执行项目迁移。
2. **沿用既有证据原则**：翻译前替换、论文生成与 CLI 编排都需要保留输入到输出的来源关系；可用界面或生成成功不能代替语义正确性。
3. **本地 AI 兼容性**：实际组件、设备／驱动及输入形状共同限定能力；无法取得模型身份或资源不足时保留具体状态，不汇总成含义不明的成功／失败。
