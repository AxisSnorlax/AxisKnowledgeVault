### P1 — Chrome DevTools MCP：取消等待与串行执行分开

[v1.13.0](https://github.com/ChromeDevTools/chrome-devtools-mcp/releases/tag/chrome-devtools-mcp-v1.13.0) 发布页显示 11 月 11 日，包含页面级网络 mock、logpoint、Windows 常见 UTF-8 BOM 配置读取，以及取消时保持任务串行等变化。

已合并的 [PR #3079](https://github.com/ChromeDevTools/chrome-devtools-mcp/pull/3079) 当前说明区分排队与执行：等待任务可移出队列；已开始工作继续持有 guard，直到处理结束。取消不强制终止浏览器操作，无法结束的处理器仍可能阻塞队列。这里依据最终说明与发行记录，不沿用讨论中已被替换的早期方案。

对 [[AxisAgent]] 的推论：取消回执与资源空闲证据分开，迟到结果保持原调用归属；不能用“调用方不等了”作为下一项冲突操作的放行依据。具体增补到 [[Deterministic Agent Runtime]]。本轮未启动浏览器自动化、网络 mock 或 logpoint。

### P2 — OpenCodeReview：零发现也要保留覆盖限制

[README](https://github.com/alibaba/open-code-review) 描述由确定性逻辑负责文件选择、分组和评论定位，Agent 负责动态上下文与审查；评测结果属于项目披露，且项目明确说明其 precision／recall 取舍。本轮未复现评测，不采用宣传的成本比例作独立结论。

[v1.13.9](https://github.com/alibaba/open-code-review/releases/tag/v1.13.9) 发布页显示 11 月 13 日，新增运行覆盖中记录排除文件，修复零发现 PR 摘要遗漏警告，并按单次请求约束工具声明。

Windows/.NET 借鉴：Review 回执保存目标 revision、实际处理／排除范围和警告；结果为空不能独自构成整仓 PASS。对 C# 项目仍需其真实构建、测试及适用分析器证据。既有 [[Agent Verification and Audit Plane]] 已覆盖证据充分性，本轮不重复追加，也未运行审查工具或发表评论。

### P3 — LoopForge：工作流定义与实际运行环境分别验证

[LoopForge README](https://github.com/Tencent/LoopForge) 描述由 Agent、Script、Human-gate 与子 SOP 节点组成的流程，围绕现有编码 CLI 保存角色、沙箱、日志及产物。可重复的流程定义不等于每次运行都已完成全部节点。

[v0.3.9-rc.1](https://github.com/Tencent/LoopForge/releases/tag/v0.3.9-rc.1) 发布页显示 11 月 13 日，明确为 Pre-release，列出避免凭据进入 clone URL、限定 CLI 配置写入范围，以及默认执行机器的页面／接口规则一致性等调整。发行材料还提供容器镜像摘要，镜像标签本身不能代替该摘要。

对 [[AxisAgent]] 的推论：调度节点、执行机器、CLI 版本和真实工作区应一起记录，重试关联原节点与已有产物。此处是架构候选，本轮未部署 LoopForge、安装其 CLI 或更改本聊天定时任务；Windows 本机可用性仍需实际执行证据。
