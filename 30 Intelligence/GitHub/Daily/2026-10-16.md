### P1 — context-mode：检索缓存与证据生命周期要分开

官方 README 描述了工具输出留在外部、按需检索，以及 SQLite/FTS5/BM25 会话检索；URL 内容缓存默认 TTL 为 24 小时，并提供强制刷新和清理机制。不同客户端对 Hook 的支持有差异，不能把指令文件等同于实际拦截。

对 [[AxisAgent]] 的借鉴是：检索结果除了内容片段，还需要来源版本和采样时间；需要复核实时变化时重新读取源。用于恢复的缓存可以过期，用于验收的证据应按独立策略保存。上述是 Axis 的设计推论，不是本轮已验证实现。

项目宣传的“98% reduction”是其自报示例，不能推导所有任务的 Token、成本或正确率收益。[README](https://github.com/mksglu/context-mode)。

### P1 — xerj：带位置的检索结果与服务访问边界

官方资料描述了目录自动索引、按片段返回 `file:line`、代码符号索引，以及 Elasticsearch 风格 API；提供 Windows 预构建发行路径。值得研究的对象是“定位并引用足够的原始材料”，而不是默认用新服务替换全部文件搜索。

README 的“40x”宣传不能与其另一个端到端案例的输出 Token 指标混用，更不能视为独立复现结果。对 Windows/.NET，可以先把它当作独立进程/API Adapter 候选，验证实际所需接口、中文检索、增量索引和内存预算。[项目资料](https://github.com/xerj-org/xerj)。

其 `--insecure` 模式关闭 TLS 和 API-key 鉴权；能访问服务的调用者拥有广泛索引权限，因此本机端口也不能自动等价于“只有当前 Agent 可访问”。Memory namespace 的权限规则需要单独核查。本轮未启用服务，也未执行安装脚本。[官方权限模型](https://github.com/xerj-org/xerj/blob/main/docs/SECURITY_MODEL.md)。

### P1 — 官方插件目录：稳定 ID 与展示名称分离

Anthropic 官方目录明确把插件 `name` 作为不可随意改动的已发布标识，展示名称另用 `displayName`；必须改名时通过显式 `renames` 映射迁移。它也允许以明确的 skills 列表包装上游 Skill 集合。

对 [[AxisAgent]] 的推论是：Catalog 名称、UI 标签和安装身份分离；升级与改名仍须保留原始来源、版本和权限记录，不能借改名自动扩大能力。规则来自特定宿主，不能宣称所有 Agent 客户端均实现了相同迁移机制。[官方目录规则](https://github.com/anthropics/claude-plugins-official)。

## 长期判断

1. **Context Budget、Cache Freshness、Evidence Retention 分开治理。** 少传输上下文不等于少保存证据，也不等于更正确。
2. **检索身份与权限一同携带。** 文档来源、版本、工作区和 namespace 应能追溯；评分不能替代源读取或权限验证。
3. **Plugin Identity 与 DisplayName 分开。** 改名、版本升级和权限变化是不同事件，应分别校验并可回滚。

以上是持续研究形成的工作假设。本次更新 [[30 Intelligence/GitHub/Agent|Agent 趋势索引]]、[[Agent Memory and Knowledge Lifecycle]]、[[Agent Capability Packaging]]；保留原有正文和历史证据，不新建平行知识节点。
