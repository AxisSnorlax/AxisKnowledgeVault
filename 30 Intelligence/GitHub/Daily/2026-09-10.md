# GitHub Trending — 2026-09-10

## 今日结论

今天最明显的变化不是“又出现一个 Agent 框架”，而是 Agent 工程化继续向上分层：**Skill 正从能力脚本扩展到输出策略与 UX 规则，Plugin 开始承载 Skills + MCP + Agents + Hooks 的可分发组合，而 Team Harness 开始把这些能力连同知识、规则和经验在团队内版本化分发。** 同时，独立的本地优先 Agent Desktop 重新进入 Trending，说明桌面工作台正在成为 Agent 的正式产品形态，而不只是 CLI/IDE 插件的外壳。

## 今日值得关注

### ayghri/i-have-adhd

- 方向：Agent Skill / 输出策略 / UX Policy
- GitHub Trending：**+4,624 stars today**，当前综合榜第一。
- 仓库：https://github.com/ayghri/i-have-adhd
- 为什么值得看：它本身技术实现不复杂，但信号很强——Skill 不再只代表“会做某件事”，也开始承载回答结构、行动顺序、信息密度和交互风格等行为策略。
- 关键做法：行动优先、步骤编号、抑制旁支、每轮重述状态、明确下一步等规则都被直接打包成可安装 Skill/Plugin。
- 对 [[AxisAgent]] 的借鉴：不要把输出风格、交互节奏、任务推进策略硬编码在单一 System Prompt 中；可考虑独立 `Behavior/Response Policy Skill`，并允许按用户/工作区切换。
- 关联：[[Agent]] · [[Skills]]

### Tencent/teamai-cli

- 方向：Team Harness / Skills Distribution / Team Context / Knowledge Recall
- GitHub Trending：**+563 stars today**，总星约 2.9k。
- 仓库：https://github.com/Tencent/teamai-cli
- 为什么值得看：它把团队级 Agent 工程明确拆成 `Team Execution × Team Context × Team Improvement`，并通过 Git 仓库分发 Skills、Rules、Docs、Agents、Hooks、MCP 等资源。
- 关键做法：
  - `push → review/merge → pull` 让 Agent 能力配置也进入代码审查流程；
  - 同一 Harness 适配 Claude Code、Codex、Cursor、OpenCode 等多个 Agent；
  - 会话结束后按“摩擦信号”识别值得沉淀的经验；
  - `recall` 结合 BM25 与代码结构图进行团队知识检索；
  - 低价值/过时知识有维护与归档机制。
- 对 [[AxisAgent]] / [[Axis Knowledge Vault]] 的借鉴：知识库不应只“存文档”，还应建立 `Capture → Review → Promote → Recall → Prune` 生命周期；Skill/Rule/MCP 等能力也应支持版本化和来源治理。
- 关联：[[Agent Harness]] · [[Skills]] · [[Memory]] · [[Context Engineering]]

### vastsa/PI-Desktop

- 方向：Local-first AI Coding Desktop / Agent Workspace
- GitHub Trending：**+393 stars today**，总星约 1.6k。
- 仓库：https://github.com/vastsa/PI-Desktop
- 为什么值得看：这是当前与 [[AxisAgent]] 产品形态最接近的新趋势项目之一：独立桌面工作台，而非 IDE 插件；支持项目、会话、Review、MCP、Skills、Subagents、插件、Context Checkpoint 和本地/云模型。
- 架构信号：明确分离 `React Renderer → Electron Main → Rust Host Core → pi Agent Sidecar → Provider`。其中 Host Core 独占文件、权限、SQLite、Secrets，Agent Sidecar 独占模型交互与 Agent Loop。
- 对 [[AxisAgent]] 的借鉴：
  - UI、特权主机能力、Agent Loop 三者应继续保持物理/进程边界清晰；
  - Permission、Filesystem、Secrets、Persistence 不应放进 UI；
  - 插件沙箱、发布者验证、Session Recovery 是 Agent Desktop 真正走向产品化后的必修项。
- 关联：[[Agent]] · [[Desktop UI]] · [[Local-AI]]

### openai/plugins

- 方向：Codex Plugins / 可分发 Agent 能力包
- GitHub Trending：**+505 stars today**，总星约 6.2k。
- 仓库：https://github.com/openai/plugins
- 为什么值得看：它比单纯的 Skills Catalog 更进一步。一个插件除了 `.codex-plugin/plugin.json`，还可以携带 `skills/`、`.mcp.json`、agents、commands、hooks、assets 等多个能力面。
- 趋势判断：Agent 能力抽象正在形成更清晰的层级：`Skill` 是工作流/行为单元，`Plugin` 是可安装能力包，`Harness` 则负责运行、治理和组合这些能力。
- 对 [[AxisAgent]] 的借鉴：未来插件模型不要只设计为“DLL 扩展”；应允许插件声明 Skills、Tools/MCP、UI Metadata、Permissions、Hooks、Assets 和版本兼容性。
- 关联：[[Agent]] · [[Skills]] · [[MCP]]

### rtk-ai/rtk

- 方向：Context/Tool Output Optimization
- Rust Trending：**+220 stars today**，总星约 79.7k。
- 仓库：https://github.com/rtk-ai/rtk
- 为什么值得看：它专门通过 CLI Proxy 压缩常见开发命令返回给 LLM 的内容，项目宣称典型命令可减少约 60–90% token 消耗。
- 趋势判断：`Context Engineering` 正从框架内部策略变成独立工具层；重点不只是模型 Context Window，而是如何从源头减少 Tool Output 噪声。
- 对 [[AxisAgent]] 的借鉴：Terminal/Git/Test/Build 工具应返回结构化摘要 + 可按需展开的原始输出，不要默认把完整 stdout/stderr 全塞进 Context。
- 关联：[[Context Engineering]] · [[Agent]]

## Windows / .NET 特别观察

### microsoft/win-dev-skills

- 方向：WinUI 3 / Windows App SDK / Agent Skills
- 仓库：https://github.com/microsoft/win-dev-skills
- 动量说明：今天不是 GitHub Trending 主榜爆点，但这是 **Microsoft 官方、且与当前 Axis 技术路线高度相关** 的项目，值得单独提升优先级。
- 关键变化：仓库以 Agent Plugins 1.0 形式提供 WinUI 3 专用 Agent/Skills，兼容 GitHub Copilot、Claude Code、OpenAI Codex；覆盖 scaffold → design → build → run → test → package → ship。
- 目前包含 WinUI 开发、设计、Code Review、UI Testing、Packaging、WPF→WinUI Migration、Setup 等 8 个 Skill，并配套 WinApp CLI、Roslyn Analyzer 与 WinRT/.NET Metadata 工具。
- 更值得注意：项目明确说明其工作流可以完全通过 `dotnet` / `winapp` CLI 运行，Visual Studio 不是必需条件。
- 对 [[AxisAgent]] / WinUI 学习路线的意义：以后重构 WinUI 3 桌面端时，可以直接把该仓库作为 Agent 编程的官方参考基线，而不是让 Codex 从通用 XAML/WPF/UWP 知识中猜 WinUI。
- 关联：[[WinUI]] · [[DotNet]] · [[Agent]]

### C# Trending 状态

- `CoplayDev/unity-mcp` 今天约 **+31 stars**，继续证明 C#/.NET 的 AI 热点主要集中在“把 Agent 接入专业桌面软件/工程工具”，而不是再造通用 Agent Framework。
- 今日没有新的 C# / WinUI / Avalonia 项目出现类似 Agent Skills 主线那样的爆发式增长。
- 结论：对 Axis 来说，差异化机会仍是 **Windows Native + Professional Software + MCP/Computer Use + Local-first Agent**。

## 与 2026-09-09 相比的趋势变化

1. **Skills 继续升温，但抽象层次变高。** 昨日重点是 Skill/Context/Memory 本身；今天 `openai/plugins`、`teamai-cli` 表明生态开始解决 Skills 如何组合、分发、审查和跨 Agent 复用。
2. **Agent Desktop 成为更明确的产品类别。** `PI-Desktop` 直接把 Agent Workspace、Permission、MCP、Skills、Subagents、Plugin、Context Checkpoint 放入独立桌面应用。
3. **Context Engineering 继续从“压缩算法”向“工具输出治理”扩展。** `rtk` 说明 Terminal/Git/Build 等结果的压缩与结构化已经值得成为独立工具。
4. **WinUI 的 Agent 开发工具链开始正式化。** `microsoft/win-dev-skills` 说明 Windows App SDK 开发正在获得专门的 Agent Skills/Analyzer/CLI 工作流，这对 VS Code + Codex 场景尤其重要。
5. **Local AI 今日没有新的推理引擎级爆点。** 更显著的变化发生在“本地优先 Agent Desktop 如何组织模型、权限、插件与工作区”。

## 对 AxisAgent 的可执行事项
