# GitHub Trending — 2026-09-12

## 今日结论

今天真正值得保留的变化有四条：

1. **Agent workflow 正从“安装 Skill”继续走向可版本化、可组合、可验证的工程流程。** `github/spec-kit`、`obra/superpowers` 与官方 `dotnet/skills` / `Unity-Technologies/skills` 同时强化了这一方向。
2. **持久知识层出现明显加速。** `nashsu/llm_wiki` 从昨日记录的约 +94/day 上升到约 **+640/day**，并且其架构明确区分 Raw Sources、派生 Wiki 与 Schema/Rules，强烈支持 [[Agent Memory and Knowledge Lifecycle]] 的分层模型。
3. **本地 AI 从静态“能否加载”继续转向真实硬件 Fit + 实测反馈。** `AlexsJones/llmfit` 从昨日约 +247/day 上升到约 **+482/day**，其真实 benchmark 可以覆盖估算结果。
4. **专业桌面软件 + Agent Surface 继续成为稳定方向。** Unity 官方发布跨 Agent Skills；`dbx` 继续采用独立 MCP Server + 分级写权限；Rust `gpui-kit` 则提供了新的高性能原生桌面 UI 观察样本。

## 今日值得关注

### github/spec-kit

- 方向：Spec-driven Development / Agent Workflow Packaging
- GitHub Trending：约 **+985 stars today**。
- 仓库：https://github.com/github/spec-kit
- 为什么值得看：它不只提供提示模板，而是把 specification、plan、tasks、clarify、analyze、checklist 等步骤组织成 Agent 工作流；同时已有 Extensions、Presets、Bundles 和版本/安装策略。
- 趋势判断：工程工作流开始出现“可组合、可版本化、可审查”的分发层，而不是把所有规则堆进单一 `AGENTS.md`。
- 对 [[AxisAgent]] 的借鉴：Skill/Plugin Manifest 应允许声明 workflow、依赖、版本与验证步骤；项目级工程规范可以被包装成可安装能力，但最终 Build/Test/Qualification 仍必须是真实门禁。
- 关联：[[Agent]] · [[Skills]] · [[Agent Capability Packaging]]

### obra/superpowers

- 方向：Skills / Agent Engineering Methodology / Verification Workflow
- GitHub Trending：约 **+731 stars today**。
- 仓库：https://github.com/obra/superpowers
- 为什么值得看：项目强调在任务开始前检查适用 Skill，并把 brainstorming、计划、TDD、systematic debugging、并行 subagent、code review、worktree、完成前验证等做成强制工作流。
- 趋势判断：`Skill` 越来越不像“知识提示词”，而更像 **可执行工程治理与行为策略**。
- 对 [[AxisAgent]] 的借鉴：Skill Engine 除内容和工具提示外，应允许表达 precondition、required checks、verification evidence 与 completion gate；但实际权限仍由 Runtime 强制执行。
- 关联：[[Skills]] · [[Agent Capability Packaging]] · [[Engineering Standards]]

### nashsu/llm_wiki

- 方向：Persistent Knowledge / Incremental Ingestion / Local-first Knowledge Desktop
- GitHub Trending：约 **+640 stars today**；昨日知识库记录约 +94/day，出现明显加速。
- 仓库：https://github.com/nashsu/llm_wiki
- 为什么值得看：其核心不是“再做一个 RAG UI”，而是把来源持续 ingest 成可维护、互联的 Wiki，并区分 Raw Sources → Wiki → Schema；支持 persistent ingest queue、变化检测、Review、wikilink/YAML，以及 Obsidian 兼容知识文件。
- 桌面实现：Tauri v2 Rust Backend + React/TypeScript/Vite，另提供受 token 保护的本机 HTTP API 与 MCP Surface。
- 对 [[Axis Knowledge Vault]] 的借鉴：继续坚持 Vault 是 **Promoted Knowledge**，不是原始聊天日志；来源哈希、增量刷新、Review Queue、可追踪派生关系应优先于无差别重新 embedding 全库。
- 关联：[[Memory]] · [[Context Engineering]] · [[Agent Memory and Knowledge Lifecycle]]

### vastsa/PI-Desktop

- 方向：Local-first Agent Desktop
- GitHub Trending：约 **+545 stars today**；昨日约 +636/day，热度略回落但仍然很强。
- 仓库：https://github.com/vastsa/PI-Desktop
- 为什么值得看：其 React Renderer / Electron Main / Rust Host Core / Agent Sidecar 分层继续提供有价值的产品架构样本；Permission、Filesystem、SQLite、Secrets、Plugin Isolation 与 Agent Loop 分离。
- 对 [[AxisAgent]] 的借鉴：继续保持 Desktop UI、Privileged Host、Agent Runtime 的边界。即使未来更换 Avalonia/WinUI/Web UI，也不应让 UI 框架迁移侵入 Runtime 与安全边界。
- 关联：[[Agent]] · [[Desktop UI]]

### AlexsJones/llmfit

- 方向：Local AI Hardware Fit / Benchmark Feedback
- Rust Trending：约 **+482 stars today**；昨日知识库记录约 +247/day，增长明显加速。
- 仓库：https://github.com/AlexsJones/llmfit
- 为什么值得看：除了 CPU/RAM/GPU/VRAM 探测和模型 Fit 估算，它还支持真实 benchmark，并允许实际测量覆盖估算结果。
- 对 [[AxisAIManager]] 的借鉴：继续推进 `Hardware Profile → Fit Recommendation → Runtime Launch → Measured TPS/TTFT/VRAM/RAM → Feedback`，UI 必须明确区分 Estimate 与 Measurement。
- 关联：[[Local-AI]] · [[AxisAIManager]]

### Unity-Technologies/skills

- 方向：Official Vendor Skills / Professional Software Automation
- C# Trending：约 **+45 stars today**。绝对增长不算大，但来源和方向价值高。
- 仓库：https://github.com/Unity-Technologies/skills
- 为什么值得看：Unity 官方开始把新建项目、CLI 等专业工作流包装成可复用 Agent Skills，并兼容 Claude Code、GitHub Copilot、Cursor、Cline 等多种 Agent。
- 趋势判断：此前 `unity-mcp` 证明“专业软件 → MCP Surface”，现在官方 Skills 又补上“专业工作流 → Domain Skills”。
- 对 Axis 产品的借鉴：[[AFSCADA]]、[[AxisProtocolStudio]] 等未来若加入 AI，不应把 Prompt 写死在 UI；更合理的是 `Domain Skills + Controlled Tool/MCP Surface + Permission`。
- 关联：[[DotNet]] · [[Agent]] · [[MCP]] · [[Skills]]

### dotnet/skills

- 方向：Official .NET Agent Skills / Plugin Marketplace
- C# Trending：约 **+13 stars today**；热度不是重点，官方工程化程度更重要。
- 仓库：https://github.com/dotnet/skills
- .NET 团队已经将 LSP、性能诊断、MSBuild、NuGet、Upgrade、AI/RAG/MCP、Testing、ASP.NET Core、Blazor 等组织为 curated plugins / skills，并提供 Skill Value dashboard 来观察 token、elapsed time、activation 与 not-passed rate。
- 对 Axis 工程体系的借鉴：Skill 本身也需要可测量质量指标；不仅要问“有没有触发”，还应记录成功率、耗时、Token、误触发/未通过率和版本回归。
- 关联：[[DotNet]] · [[Skills]] · [[Agent Capability Packaging]]

### t8y2/dbx

- 方向：Rust Native Desktop + Separate MCP Surface
- Rust Trending：约 **+265 stars today**；昨日约 +238/day，保持稳定增长。
- 仓库：https://github.com/t8y2/dbx
- 为什么值得看：数据库客户端本体保持轻量，同时将 MCP Server 独立分发，并明确区分 read-only / safe-write / high-risk-write 权限。
- 对 Axis 专业工具的借鉴：Agent Surface 可以独立于主 UI 生命周期；读、普通写、高风险写应该拥有不同 Permission Contract，而不是一个 `CanWrite=true`。
- 关联：[[Agent]] · [[MCP]] · [[Desktop UI]]

### longbridge/gpui-kit

- 方向：Rust / GPUI Native Desktop Component System
- Rust Weekly Trending：约 **+486 stars this week**。
- 仓库：https://github.com/longbridge/gpui-kit
- 为什么值得看：提供 60+ 原生桌面组件，并把 behavior/infrastructure 与 presentation/application 分层；项目自身宣称可构建高帧率 GPU UI，并已用于商业桌面产品。
- 真实性边界：其性能数字属于项目自身声明，不能据此判断它一定优于 Avalonia/WPF/WinUI/WebView2。
- 对 [[AxisAgent]] 的借鉴：在 UI Framework Qualification 中可把 GPUI/Rust-native 作为“生态外基准样本”，重点研究组件层次、Markdown/HTML/图表/扩展能力和性能方法，而不是立即引入 Rust 重写现有 C# Runtime。
- 关联：[[Desktop UI]] · [[Avalonia]] · [[WinUI]]

## 与 2026-09-11 相比的趋势变化

1. **Knowledge 方向最明显的变化是 `llm_wiki` 加速。** 从约 +94/day 到约 +640/day，使“Persistent Promoted Knowledge”不再只是小众信号。
2. **Skills 的定义进一步扩大。** `superpowers` 强调工程行为/验证流程，`spec-kit` 强调规格与可组合 workflow，官方 .NET / Unity 则开始提供领域 Skills；这比单纯的 SKILL.md 目录更接近正式能力资产。
3. **Local AI Fit 从估算走向闭环测量。** `llmfit` 今日增速近乎翻倍，真实 benchmark 覆盖 estimate 的模式值得长期跟踪。
4. **Agent Desktop 仍强，但今日没有新的架构突破。** `PI-Desktop` 热度略回落，仍提供持续验证，不需要重新写一套结论。
5. **WinUI/WPF/Avalonia 本身今日没有足够强的新框架级信号。** Avalonia Daily 仍有普通活跃度，但不应为了日报机械更新长期索引。
6. **Rust Desktop 出现值得观察的新 UI 样本。** `gpui-kit` 更适合纳入 UI Framework Qualification 的研究对照，而不是成为立即迁移目标。

## 对 Axis 的可执行事项

- [ ] Skill Manifest 增加 workflow/check/verification metadata 的设计研究，区分“知识 Skill”与“工程治理 Skill”。
- [ ] 给 Skill/Plugin 引入可测量质量指标：activation、success/not-passed、elapsed time、token cost、版本回归。
- [ ] Axis Knowledge Vault 评估 Source Hash、Incremental Refresh、Review Queue 与派生知识可追踪关系。
- [ ] AxisAIManager 设计 Estimate 与 Measured 两套性能字段，并保留 benchmark provenance。
- [ ] 专业软件 AI Surface 继续采用 `Domain Skills + MCP/Tool + Permission`，不要把 Agent 逻辑耦合进页面。
- [ ] AxisAgent UI Framework Qualification 可加入 `gpui-kit` 作为架构/性能研究样本，但框架选择仍以同页、同数据、同机器 Benchmark 为门禁。
