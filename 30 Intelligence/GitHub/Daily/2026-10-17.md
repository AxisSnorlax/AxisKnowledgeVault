### P1 — Llama-Windows：控制面负责实际执行边界

官方 README 将其描述为 Windows 11 的 WinUI 3 应用，管理独立的 `llama serve` 进程并通过 REST 通信，使用标准 Hugging Face 缓存；源码构建要求 .NET 10。对 [[AxisAIManager]]，这支持“原生桌面控制面 + 独立推理 Runtime”的参考路线。[README](https://github.com/ggml-org/Llama-Windows)。

本次复核的 **v0.12.0 发布于 10 月 10 日，并非今天的新发布**。其发布说明包含：对非 loopback 暴露加入 API-key 保护；拒绝自定义参数覆盖应用负责的安全开关；自动更新缺少固定脚本哈希时跳过执行。这里采纳的是工程边界，不据此宣布本机已通过安全验收。[v0.12.0 发布说明](https://github.com/ggml-org/Llama-Windows/releases/tag/v0.12.0)。

对 [[AxisAgent]] 的设计推论：UI 显示值、保存配置和实际进程参数必须一致，不能让“额外参数”绕过已经作出的权限决定。进一步记录在 [[Agent Capability Policy Enforcement]]。

### P2 — Magnitude：调优结果需要绑定实验条件

官方 README 描述按模型与硬件调整内核、推测解码，以及对外提供兼容 API。Windows 在其声明的支持范围内；“2x faster”及图中 Mac/NVIDIA 平均指标都是项目方公布的比较，不能泛化为本机全部模型或 AMD/CPU 的结论。[项目资料](https://github.com/magnitudedev/magnitude)。

本仓库 9 月 30 日日报已记录该项目，今天不重复建立模型。对 Windows/.NET 的借鉴仍是独立 Runtime Adapter 与同机验证：固定模型、量化、上下文、驱动和运行时版本，分别记录预填充、解码、并发、资源占用和质量。调优参数只是候选，需要经过与基线相同的正确性检查。

### P2 — CLI-Anything：结构化命令之后仍需验证产物

上游以 JSON/CLI 包装专业软件能力，并描述真实应用后端调用和产物检查。它提供的“生成工程文件 → 调用真实后端 → 验证输出”思路，与 [[Professional Software Agent Surface]] 和 [[Agent Verification and Audit Plane]] 的既有判断一致。[官方仓库](https://github.com/HKUDS/CLI-Anything)。

对 .NET 工程工具，返回 JSON 或退出码为零不应单独决定成功；结果格式、关键内容和真实后端是否执行应分别验证。上游测试数量与通过率属于自报，本轮未独立运行，也不把所有生成的 CLI 视为同等成熟。

## 长期判断

1. 桌面 UI、运行时控制面、推理进程分别演进；进程分离本身不等于权限隔离。
2. 启动配置属于执行合同，应用负责的网络/凭据/安全参数不能被自由文本覆盖。
3. 性能、兼容性和输出正确性分别验收；第三方宣传与本地测量分开保存。

## 后续验证建议

- 对 Local AI Host 检查 UI 配置与实际启动参数是否一致，以及配置失效时是否保守回退。
